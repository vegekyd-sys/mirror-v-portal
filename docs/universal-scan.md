# 统一扫码入口

桌面 `/onboard` 从运行时读取 Agent 模板，默认选中 Mirror V，生成一个有十分钟有效期的 Portal 入口码。入口码只包含 `https://mirror-v-portal.vercel.app/onboard/scan?entry=...`；切换模板时会取消旧入口并生成新入口。打开页面本身不会提前创建飞书或微信授权会话。

手机扫开入口后按 App 的 User-Agent 分流：飞书创建一个 `registerApp` 授权会话并打开飞书验证链接；微信创建一个 iLink 授权会话并打开微信 `liteapp` 链接。未识别的扫码器在手机页选择飞书或微信。每个入口只允许关联一个原生授权会话；电脑通过入口状态接口显示进度。飞书或微信确认后，现有流程才创建 Agent 实例并绑定频道。

这实现了“扫描同一张入口码一次，再在所用 App 中完成确认”。App 授权确认或微信验证码仍由平台决定。钉钉目前仅有已有实例的凭据绑定接口，尚无扫码创建新实例的接入；入口页对此明确提示，后续应增加对应的授权适配器和端到端验收。

入口及原生授权状态目前保存在中央网关和 runtime-manager 内存中。服务重启会使未完成的扫码过期，用户可在桌面重新生成。`PORTAL_BASE_URL` 可覆盖入口码中的公开域名，默认使用 `https://mirror-v-portal.vercel.app`。
