# 统一扫码入口

桌面 `/onboard` 从运行时读取 Agent 模板，默认选中 Mirror V，生成一个有十分钟有效期的 Portal 入口码。入口码只包含 `https://mirror-v-portal.vercel.app/onboard/scan?entry=...`；切换模板时会取消旧入口并生成新入口。打开页面本身不会提前创建飞书或微信授权会话。

手机扫开入口后按 App 的 User-Agent 分流：飞书创建一个 `registerApp` 授权会话，并在确认页提供“在飞书继续授权”按钮；微信创建一个 iLink 授权会话，确认页提供用户主动点击的“在微信确认开通”按钮。微信返回的 `qrcode_img_content` 官方定义为用于展示二维码的 URL 或内容，不保证直接打开为普通网页，因此页面同时展示原生授权码；如果点击后微信仍显示空白，用户返回确认页长按授权码，选择“识别图中二维码”。页面不会自动跳转。未识别的扫码器在手机页选择飞书或微信。每个入口只允许关联一个原生授权会话；电脑通过入口状态接口显示进度。飞书或微信确认后，现有流程才创建 Agent 实例并绑定频道。

这实现了“用同一张 Portal 入口码进入，再在所用 App 中完成确认”。微信的一次点击直达效果还需在真实客户端验收；长按识别是已提供的备选入口。App 授权确认或微信验证码仍由平台决定。钉钉目前仅有已有实例的凭据绑定接口，尚无扫码创建新实例的接入；入口页对此明确提示，后续应增加对应的授权适配器和端到端验收。

入口及原生授权状态目前保存在中央网关和 runtime-manager 内存中。服务重启会使未完成的扫码过期，用户可在桌面重新生成。`PORTAL_BASE_URL` 可覆盖入口码中的公开域名，默认使用 `https://mirror-v-portal.vercel.app`。
