## 二、需要平台层做的（关键卡点）

### 2.1 定时调度（必须 per-tenant）

这两条 job **不在镜像层 entrypoint 里**（会真实发营销邮件 / 触发 smart-reply，
开不开是每个租户的决定）。客户实例上没人 inject → 不会自动跑。

调度器是 OpenClaw Gateway 内置 scheduler，**不是系统 crontab**——容器里没有 `crontab`
命令也没有 cron 守护进程，往 crontab 写任务会静默失败。在租户实例里执行：

```bash
cd <agent_workspace>/work/mio-api
bash inject_marketing_automation_cron.sh inject   # 出站 · 每 30 分钟
bash inject_marketing_inbound_cron.sh inject      # 入站 · 每 15 分钟
```

两个脚本都是幂等的（`--declaration-key`），注册完会回读 Gateway 复查，
挂不上就非零退出。查现状用 `status`，立刻补跑一次用 `run-now`。
全套定时任务体检：`bash dc_cron_doctor.sh`。

**要求**：每个租户/实例按**各自的 workspace + `MIO_CDP_SUPPLIER_ID`** 配这两条。
> 参考：`HEARTBEAT.md` 已写明「本 Agent 的自主定时运行需配置层显式开启」——同一原则。

### 2.2 generator 运行前提

`dc_marketing_automation_generator.openclaw_generator` 调 `openclaw agent --agent dealclaw --thinking off --message-file ... --json`。
**要求**：客户环境必须有 `openclaw` CLI，且注册了 `dealclaw` agent（workspace 指向该租户）。

### 2.3 每租户配置项
- `MIO_CDP_SUPPLIER_ID`（企业 key）
- 发件身份（默认 `V@mail.dealclaw.io`，或租户自有）+ **Resend 域名预热**
- 飞书绑定（回信通知）

## 五、怎么临时停

```bash

bash work/mio-api/inject_marketing_inbound_cron.sh remove
```
