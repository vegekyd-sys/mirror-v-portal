# Mirror V 全功能 · 回归评测标准

适用：模板 `mirror-v-full`（V 9.1 runtime + Worker + 记忆 + 桌面/V Browser/语音）在 Portal 上的每个实例。
执行器：`deploy/mirror-v/eval/eval.mjs`（随 Portal release 部署，在 Portal 主机上运行）。

## 为什么分三层

真人反馈是「用着用着不能用了」。回看 10/08–10/12 的事故，没有一个是「某个功能从来不工作」，全是**用一段时间后才出现的状态问题**：

| 日期 | 现象 | 根因 | 现在由哪条用例守住 |
|---|---|---|---|
| 10/08–09 | 测试实例 19 小时不睡、一直计费 | 闲置实例永远拿不到新脚本，旧 quiesce 误判后台任务 | H2、E1、E10 |
| 10/09 | 回复完一直「运行中」，下一条排队 83 s | 导入记忆后每轮备份 294 MB | H5、E4、E8 |
| 10/09 | 首字慢、调工具前不说话 | DeepSeek 思考回合文字被扣到最后 | A2、A3、A4 |
| 10/09 10:41 | 一次模型超时后所有消息被拒 | 运行时报告的失败也把实例锁成 blocked | H1、E6 |
| 10/09 21:02 起 3 天 | 实例锁死，任何消息都失败，定时任务也全停 | 闲置休眠 stop 超时被当成 blocked | H1、H4、E7 |
| 10/12 门禁发现 | 备份涨到 56 MB、每轮 >10 s | 用过 /vds 后 Codex 把插件市场 git 仓库克隆进 CODEX_HOME/.tmp | H5、E4 |
| 10/12 门禁发现 | 并行子 agent 的结果丢失 | 模型用 sessions_yield 交出回合，Gateway 之后自己唤醒汇总，回复没有渠道送出 | B7 |

所以标准分三层：

1. **L0 生产健康巡检**：每 10 分钟扫所有真实实例，不调模型、不唤醒沙箱。专抓「用着用着坏了」。
2. **L1 发布门禁**：每次 Portal release、快照、V 版本跟进之前，在测试实例上跑一遍功能回归。P0 全过才能上线。
3. **L2 耐久回归**：每晚在专用实例上模拟几天的使用（多轮对话、睡醒循环、大记忆、故障注入），抓退化。

## L0 生产健康巡检（每 10 分钟，`eval.mjs health`）

只读 Portal 数据库，不唤醒沙箱。任一 **告警** 项触发即退出码 2 并写入 `/opt/nexus/data/eval/health.jsonl`。

| ID | 检查 | 告警阈值 |
|---|---|---|
| H1 | 有实例处于 `blocked` | 任何一个，立即 |
| H2 | 闲置后睡不下 | 连续 ≥ 3 次 `idle-deferred`（附 quiesce 给出的原因） |
| H3 | 最近 3 轮用户消息有 ≥ 2 轮 failed/uncertain | 是 |
| H4 | 系统定时任务（心跳、Librarian、质检、午夜报告）该跑没跑或失败 | 过点 30 分钟未成功 |
| H5 | 每轮状态备份 | `backupMs` > 15 s 或备份文件 > 80 MB |
| H6 | Portal runtime-manager 事件循环滞后 | 1 小时内 > 1 s 的次数 ≥ 30 |
| H7 | 首字（飞书收到消息→卡片出字） | 最近 10 轮 p50 > 15 s |
| H8 | 回复后长尾（模型完成→run 完成） | 任一轮 > 30 s |
| H9 | 飞书长连接 | 非 `connected` 超过 5 分钟 |
| H10 | 官方定时任务按时成功（Librarian 21:00、质检 22:00、Heartbeat 8:30/20:30、午夜报告、Skill 周复盘） | 某一项在它的周期内（日任务 26 h、Heartbeat 13 h、周任务 8 天）没有一次成功 |
| H11 | Librarian 真的干了活 | 最近一次成功但工具调用 < 3 次或回复不到 20 字（空跑） |

## L1 发布门禁（`eval.mjs gate`，约 50 分钟；`--quick` 跳过睡醒段约 30 分钟）

在测试实例 `mvfull-accept-04` 上跑。消息经 Portal 管理接口进入（和飞书走同一条 run 管线），断言读 Portal 事件和沙箱内部状态。**P0 全部通过才允许上线；P1 失败要在发布说明里写明并由 Tianyi 确认。**

## L2 耐久回归（每晚，`eval.mjs soak`）

专用实例 `mvfull-soak-01`，一晚模拟约三天的使用：

1. 导入 V001 示范记忆（大记忆，复现 10/09 的 594 MB 库）。
2. 30 轮混合对话（文本、工具、记忆写/读、Makaron），每轮记录首字、长尾、备份时长。
3. 3 次「闲置 → 睡下 → 唤醒」循环；每次唤醒后跑 E2 和一轮 A2。
4. 故障注入：回合中途杀 Gateway（E6）。
5. 手动触发一次 Librarian 和心跳。

**退化判定**：和前一晚比，首字 p50、长尾 p90、备份 p90、唤醒耗时任一项变差 > 50%，或出现任何 blocked / 睡不下 / 失败轮，记为退化并告警。

## 发布规则

1. 改 runtime 脚本、Portal、快照、V 版本跟进：先 `eval.mjs gate`，P0 全过再切 `/opt/nexus/current`。
2. 上线后 30 分钟内看一次 `eval.mjs health`。
3. 新发现的事故必须补一条用例（写进本表和 `cases.mjs`）后才算修完。
