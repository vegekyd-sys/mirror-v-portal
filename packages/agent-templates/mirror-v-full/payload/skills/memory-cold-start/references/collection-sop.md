# 采集 SOP —— 五条实测踩坑 + 飞书知识库采集

> 这些不是推断，是在 Versa 和本机 lark-cli 上真跑出来的。每条给出现象、原因、可操作步骤、停手判据。

---

## ① SPA 官网：首页 fetch 只能拿到 `<title>`，正文在 JS 包里

**现象**：`web_fetch https://www.versa-ai.com` 回来的 HTML 里只有一个 `<title>`，`<body>` 是空的 `<div id="app">`。看起来像「这家公司官网没内容」，其实是 Vue / React 单页应用，正文在打包后的 JS 里当 i18n 词条。

**步骤：**

1. `web_fetch` 首页，看 `<body>` 里有没有实际文字。只有一个挂载点 `<div id="app">` 就走下面。
2. 从首页 HTML 里 grep 出 `<script src="...">`，找 `/js/app.<hash>.js`（Vue CLI 默认命名）或 `/assets/index-<hash>.js`（Vite）。
   实测路径：`https://www.versa-ai.com/js/app.7ded5e48.js`
3. `web_fetch` 这个 JS 文件（它是文本，不是二进制，可以直接读）。
4. 在里面找 i18n 词条对象 —— 通常是一大段 `{zh:{...},en:{...},ja:{...}}` 或 `messages:{...}`。Versa 实测拿到中英日三语全量文案。
5. 顺带抓 `/js/chunk-vendors.*.js` 之外的业务 chunk，产品页 / 关于我们 / 时间线常常各在一个 chunk 里。

**判据**：抽出来的词条能拼出「公司一句话 + 产品列表 + 时间线」就够了，不要把整个 JS 包塞进记忆。

**停手条件**：JS 包里也找不到中文正文（纯图片站 / 全量 SSR 到 CDN），退回 `web_search`，并把「官网正文抓不到」本身记成一条事实。

## ② 官网媒体墙只有标题没链接 —— 逐条反查，**最多 8 条**

**现象**：「媒体报道」板块列了 19 条标题（「36氪：Versa 完成 B 轮」之类），但卡片不带 `<a href>`，或者链到一张截图。标题本身不是来源，不能直接当事实写进记忆。

**步骤：**

1. 把标题全量列出来，编号。这一步零成本。
2. **按价值排序**，只反查前 8 条：融资 / 用户量 / 获奖 / 合作方 这类会被对外引用的数字优先；普通产品更新放后面。
3. 每条 `web_search "<标题关键词> <公司名>"`，命中原文就记 URL + 发布日期 + 媒体名。
4. 每条打一个标签，三选一，**必须出现在产物里**：
   - `已核实原文` —— 找到第三方原文，带 URL 和日期
   - `仅标题` —— 官网列了，第三方搜不到原文
   - `未找到` —— 搜了，确实没有
5. 第 9 条起统一标 `未反查`，列出标题清单，告诉主人「这几条我没查，要查你说一声」。

**为什么卡 8 条**：单轮 600 秒硬上限，一次 `web_search` + 一次 `web_fetch` 现实耗时 15–30 秒，8 条已经吃掉采集预算的一半。查到第 12 条超时，整轮白做还会把租户打成 blocked。

**判据**：产物里 19 条每条都有标签，没有一条是裸标题。

## ③ 同名干扰项先排除

**现象**：搜品牌名会搜到完全无关的同名公司，混进记忆后会污染后面所有检索。

**实测**：`makaron.ai` 是法国南锡一家同名 IT 咨询公司，和 Versa 的「马卡龙玩图 / Makaron」没有任何关系。

**步骤：**

1. 搜品牌名拿到的每个域名，先对一遍：注册地、行业、页面语言、有没有提到主人给的那个公司全称。
2. 对不上的，**当场排除，并且写一条消歧义进记忆**，不要默默丢掉 —— 下次采集（或者三个月后主人自己搜）会再撞一次。
3. 消歧义写在实体页首段的 `关键词：` 行旁边，或者单列一行：
   ```
   注意：makaron.ai 是法国南锡的同名 IT 咨询公司，与本公司无关（2026-10-20，web_search）
   ```

**判据**：实体页里每个被排除的同名项都留了一行，带日期和来源。

## ④ 私有端点不采集，但要记一条「这里有东西，我没读」

**现象**：扫子域名会撞到内部系统。实测 `git.versa-ai.com` 返回 GitLab 的 `/users/sign_in` 登录页。

**规则：**

- **不尝试登录、不猜密码、不扫目录、不碰 API。** 返回登录页 = 到此为止。
- **但不要假装没看见。** 在记忆里记一行：
  ```
  git.versa-ai.com — 自建 GitLab，返回登录页，未采集（2026-10-20，HTTP 探测）
  ```
- 这一行写进对应的项目页：它是一条「我知道这里有什么，但我拿不到」的边界，主人以后想补，照着它补。

**为什么这条反而加分**：主人看到你列出了边界却没越界，比你多采到两页内容有用得多。这是信任动作。

**判据**：每个探到的私有端点在记忆里有且仅有一行，内容是「是什么 + 为什么没读」，不含任何尝试登录的痕迹。

## ⑤ 单一来源的数字标「仅官网口径」，不和媒体口径合并

**现象**：同一件事两个公开来源数字打架。实测 Versa 天使轮：投资界写 `2017.04`，第一财经写 `2017.07 / 600 万`。

**规则：**

- **两个口径都留着，各自带来源和日期。不擅自二选一，不取平均，不挑「看起来更可信的那个」。**
- 只有官网说过、第三方零命中的，统一标 `仅官网口径`。实测 Versa 有两条属于这类：「助力华为鸿蒙、亮相 HDC、联合创立新实验室」和「共青团微博力推」。
- 写法：
  ```
  天使轮：2017.04（投资界）/ 2017.07、600 万（第一财经）—— 两个公开口径不一致，待主人确认
  助力华为鸿蒙、亮相 HDC —— 仅官网口径，第三方无印证（2026-10-20）
  ```

**为什么重要**：这正是「口径守护」的卖点。对做品牌 / 市场的对接人，「我替你守着这几条，没你确认我不对外说」比「我抓到你们官网错了」强得多 —— 对外口径很可能就是他负责的。

**判据**：产物里「我拿不准的」区块排在「我查到的」**前面**，每条写清楚谁说的、哪天、有没有第二来源。

## 飞书知识库采集

**先说适用范围（否则会白写一套流程）：**

沙箱里**没有飞书凭据**（见 `TOOLS.md` 的「不可用 / 需要主人提供」）。本节今天只适用于两种场景：

1. **主人在真人轮里用 `v_browser_*` / `desktop_handoff`** 操作他自己已登录的飞书 —— 只能真人轮，`v_browser` 在 cron / heartbeat / subagent 里 fail-closed（`skills/v-browser-device/SKILL.md:110-119`，故意设计，不要绕）。
2. **平台侧 L2 连接器上线后** —— 已实测可行：`user_access_token` 路线（`lark-cli whoami` → `identity: user`），读到的范围 = 这个人自己能看到的，不需要逐个文档加协作者。平台要做的是把 OAuth 搬到 Portal，不是从零摸索。

在这两种情况成立之前，**不要向主人承诺「我去读你们飞书」** —— 走 `no-api-playbook.md`。

### 第 1 步 · 盘点（只读目录，不碰正文）

```bash
# 列所有知识空间
lark-cli wiki +space-list --page-all --page-size 50 --format json

# 逐空间列节点树（递归时带 --parent-node-token）
lark-cli wiki +node-list --space-id <space_id> --page-all --page-size 50 --format json
lark-cli wiki +node-list --space-id <space_id> --parent-node-token <token> --page-all --format json
```

- `--space-id my_library` 是**个人文档库**，只在 `--as user` 身份下可用。企业客户的散装个人云文档都在这里。
- 递归深度设 6 层封顶，防止环。
- 实测口径：13 空间 / 117 节点 / **41.4 秒**。类型分布 `doc 70 / docx 36 / bitable 9 / mindnote 1 / sheet 1`。

盘完产出一张表（空间 / 节点数 / 性质 / 建议读不读），端给主人勾。**这一步到此为止，不要顺手去抓正文。**

### 第 2 步 · 正文（**两条 API，不是一条**）

| 类型 | 命令 | 取哪个字段 |
|---|---|---|
| `docx`（新版） | `lark-cli docs +fetch --doc <token> --doc-format markdown --detail simple` | `data.document.content`，自带 `<title>` `<callout>` 等结构标签 |
| `doc`（**老版**） | `lark-cli api GET /open-apis/doc/v2/<token>/raw_content` | `data.content`，纯文本 |
| `bitable` | `lark-cli base` 的 record 接口（未实测，一张表一个 schema） | — |
| `sheet` / `mindnote` | 各自独立 API（未实测） | — |

**这条必须写死在代码里：老版 `doc` 走 `+fetch` 会直接报**

```
3380002 Unsupported document type 'doc'. Only docx is supported.
```

**实测 117 个节点里 70 个（60%）是老版 `doc`。** 只按 docx 实现的 ingestion 会**静默丢掉六成内容** —— 而且错误发生在单文档层面，批量跑的时候很容易被当成个别失败略过。

所以采集循环必须：按节点的 `obj_type` 分支；两条路都失败时**计数并上报**，不要吞。跑完报一行 `成功 N / 跳过 M / 失败 K`，K>0 就把失败清单列出来。

### 第 3 步 · 默认排除名单（在抓正文之前过滤）

**按空间名排除：**

- 飞书自带的「示例知识库」「Wiki samples」「知识库使用指南」—— 实测 9 个节点全是样例，会污染任何自动冷启动。

**按标题关键词排除（命中即不抓正文）：**

```
凭证  密码  账号  secret  token  key  身份证  银行卡  私钥  credential
```

实测 `客户交付相关` 空间下有 `客户TK账号凭证库`（bitable）和 `客户TK账号凭证查询 SOP`。

**命中后怎么做**：不是无视，是在 index 里留一行

```
- 客户交付相关 / 客户TK账号凭证库（bitable）— 标题命中凭证关键词，未读取正文（2026-10-20）
```

让主人看见你知道边界在哪。这一行本身就是信任建立的动作。

**第二道防线**：落盘时 `onboard-collect.py` 会复用 `librarian-adopt-untracked.py` 的 secret 正则就地脱敏。排除名单是第一道，不要只靠第二道 —— 企业接口文档会被 `(api_key|secret|token|password)\s*[:=]` 整片命中，那些页会永远进不了 git。

### 第 4 步 · 落盘

每份正文走同一条命令，不要手写文件：

```bash
python3 scripts/onboard-collect.py add \
  --source feishu --url <飞书文档链接> --title <节点标题> --stdin
```

**每批 ≤10 份**，批与批之间跑一次 `onboard-budget.py --pending <待入库目录>`。
