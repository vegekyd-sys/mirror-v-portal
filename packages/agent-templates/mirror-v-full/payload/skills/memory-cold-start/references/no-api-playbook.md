# 主人不授权飞书、或者资料不在飞书时的几条路

飞书文档库优先走 lark-cli（`feishu-lark-cli.md`）。这里是它走不通时的退路：主人不想授权、资料在钉钉 / Notion / 本地，或者只有零散几份。

## 开口第一件事：主动告诉主人别发文件

**主人发 pdf / docx / xlsx / zip 会被静默丢弃 —— 文件不会到达你这里，而且他收不到任何错误。** 入站白名单硬编码在 `packages/runtime-manager/src/feishu.ts:203`，只有 `["text","image","post"]` 三种，其余在 `receive()` 第一行就 return，无任何反馈。

后果是最坏的那一种：主人以为发了，你以为他没发，双方都不知道断在哪。所以这句话**必须在你需要资料之前主动说出口**，不能等他发完再解释。

建议话术（真人轮和推送版都能用）：

```
对了 —— 别给我发 pdf / word / 压缩包，那条通道没开，你发了我这边
收不到而且不会报错。能用的是：粘正文、发截图、发链接。
这是我的短板不是你的操作问题。
```

说完立刻给替代路径，不要只说「不行」。

## L0 · 公网（0 分钟，默认动作，不是备选）

**能拿到**：官网（含 SPA 的 JS bundle i18n 词条）、媒体报道、App Store 页、论文、工商公开页、招聘页。

**做法**：见 `collection-sop.md` 第 ①②③④⑤ 条。

**上限**：

- 只能拿到「对外叙事」—— 产品线、融资、公开人物、获奖。Versa 实测约 15–19 页。
- 拿不到：当前业务一句话、组织架构、定价结构、交付 SOP、历史决策。这些要靠主人的文档或他在别的 AI 助手里的记忆来补。
- 反查媒体最多 8 条（回合预算）。
- 返回登录页的私有端点不采集，只记一行「这里有东西，我没读」。

**什么时候就该停**：三轮 `web_search` 搜不到公司名 + 法人 + 产品名，就老实说「你们在公开网络上基本没有痕迹 —— **这本身是一条结论，我记下来了**」，然后转向别的来源（主人在别的 AI 助手里的记忆、主人粘贴的资料），或者先从零开始、边聊边记。

---

## L1 · 主人粘正文（每次 1 分钟，性价比最高）

**能拿到**：主人愿意粘的任何纯文本，没有实际字数上限。一两千字的一段就足够补掉一个大缺口。

**话术**：要具体，不要开放式邀请。

```
随便挑一个洞，把能说明它的那段正文粘给我。一两千字就够。
比如「你们标准交付周期」那条，把交付 SOP 里相关的那一节贴过来就行。
```

**上限与注意**：

- 不要一次要三段。一次一个洞，粘完当场落盘 + 当场给反馈（「这段补上了缺口 ④，我写成了一页，你看一眼」），主人才会粘第二段。
- 粘进来的内容走 `onboard-collect.py add --source paste`，脱敏和体积闸门在脚本里。
- 主人粘的东西里可能带内部链接和联系方式 —— 脱敏规则照常跑，不因为「是主人自己给的」就放过。

---

## L1 · 主人发截图（每次 1 分钟，适合表格和界面）

**能拿到**：主人屏幕上看得见的任何东西。表格、组织架构图、后台界面这类「粘不下来」的内容只能走这条。

**硬上限（`inbound-media.ts`）**：

| 项 | 上限 |
|---|---|
| 单条消息图片数 | **4 张** |
| 单张大小 | **10 MB** |
| 单条消息总计 | **12 MB** |
| 格式 | jpeg / png / webp / gif |

超限的部分怎么处理不要赌 —— 告诉主人「一次最多 4 张，多了分两条发」，比事后发现缺图好。

**注意**：截图是图片，不是文件，所以它**能**进来 —— 这正是主人想发 pdf 时的替代方案（「那份 pdf 你截两张图给我就行」）。

---

## L1+ · v_browser 与 desktop_handoff（5–10 分钟，**只能真人轮**）

**能拿到**：等同主人本人在他自己浏览器里看得见的一切 —— 包括飞书知识库、内部后台、需要登录的系统。

**两个工具的分工**：

- `v_browser_*` —— 操作**主人自己电脑上的 Chrome**（他已登录的账号）。流程见 `skills/v-browser-device/SKILL.md`：`v_browser_pair` 发配对码 → 主人粘进扩展 → `v_browser_devices` 确认在线 → `v_browser_acquire` 拿 `browserParams` → 用完 `v_browser_release`。
- `desktop_handoff_request` —— 发一个接管链接，主人打开后**在你的沙箱桌面上**亲手操作（登录、扫码、过验证码），完成后点「交还给 V」唤醒你。链接 10 分钟内有效，接管会话最长 30 分钟。

**fail-closed 是故意设计，不要绕**：`v_browser` 在 cron / heartbeat / subagent 里会拒绝，报 `no trusted Channel sender identity is available`（`skills/v-browser-device/SKILL.md:110-119`）。这不是故障，是设计 —— **永远不要**从定时任务里启动对主人 Chrome 的新操作。定时任务里**不能**排这条路，只能在真人轮做。

**合规话术 —— 这一条比技术更重要**：

对有内控的企业，「在第三方环境登录公司账号」默认**不要主动提**。对接人连试都不敢试，提了反而把你从「有用的工具」推成「风险项」。

真要提（比如主人自己问起、或者这是唯一能补上关键缺口的路），必须标注：

```
这一步需要你们信息安全同意。
我要做的是：在你自己的电脑、你自己的浏览器里，用你已经登录的身份
打开某个页面并读取内容。全程你能看见，随时可以收回。
但这属于「第三方工具接触内部系统」，走不走要你们那边点头。
不走也完全可以，我们回到粘正文那条路。
```

**上限**：

- 只能真人轮，主人必须在场。
- 单轮 600 秒硬上限 —— 一次操作做一件事，别排长流程。
- `download` / `waitForDownload` 不在 V Browser 契约里，需要下载的任务报「不支持」，不要当 bug 修。
- 拿到的内容照样走 `onboard-collect.py add --source browser`，照样脱敏、照样剥二进制。

## 四条路怎么选

| 情况 | 走哪条 |
|---|---|
| 刚开始，什么都没有 | L0，默认动作，不用问 |
| L0 跑完，缺口清楚了 | L1 粘正文，一次一个洞 |
| 内容是表格 / 界面 / 架构图 | L1 截图，≤4 张 |
| 主人想发 pdf | 告诉他截图或粘正文，**不要只说不行** |
| 关键缺口只能登录才拿得到，且主人在场、且企业没有内控顾虑 | L1+，并标注需要信息安全同意 |
| 定时任务里 | **只有 L0**。L1 要主人动手，L1+ fail-closed |
| 以上都不够 | 在项目页记一行「这里有什么、我拿不到」，等平台接上正式连接器（L2）再补 |

**一条底线**：拿不到就如实说拿不到，记一条缺口。**不要用推测填空** —— 被发现一次编造，前面六天的信任全部归零。
