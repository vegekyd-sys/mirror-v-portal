# 飞书 Base 排期写入

把发布时间写进飞书多维表的排期任务（成片清单、发布表）用这一套：先看字段定义，再写值，改过字段定义就整批重写，最后用脚本校验。抽查看不出这类错误。

## 1. 先读字段定义，别先写值

`lark-cli base +field-list` 只给字段名和类型，显示格式要用 `+field-get --field-id`。

- `type: datetime` + `style.format: "yyyy/MM/dd"` → 表里只显示日期，时分被吞掉，用户会说「看不到发布时间」，值其实一直在。
- 要让人看到时间，用 `+field-update --json '{"name":"…","type":"datetime","style":{"format":"yyyy/MM/dd HH:mm"}}' --yes`（全量 PUT，必须带 name 和 type，缺一个报 `Required.`）。
- 用户说「某一列看不到」而值确实存在时，再查是哪个视图隐藏了列，不要重复写数据。

完成标准：字段 `style.format` 含 `HH:mm`。

## 2. 写入：两列由同一个时刻换算

- datetime 列只收 ISO：`"2026-11-05T16:00:00+08:00"`。带中文或时段文本（如「11-05 09:00-11:00（CET）」）写进去会报 800010403，看起来像字段不可写。
- 文本列（当地时段）必须由同一个 datetime 按时区差算出，不要分别手写：印尼 WIB −1、阿联酋 GST −4、德国/西班牙/法国 CET −7、巴西 BRT −11、墨西哥 −14。
- 账号多条时按市场错峰 30 分钟，并跳过当地周末（阿联酋周五周六、德国周日）。

完成标准：每条记录两列都存在，且文本列时间 = datetime + 该市场时区差。

## 3. 改过字段定义，就整批重写

`+field-update` 是 PUT 全量更新，会重新解释已存的 datetime，实测出现过整列前移一天：当地列显示 11-05，datetime 变成 11-04，于是用户看到「这几天没排」。

- 改完字段定义立刻重读全表，逐条比对预期值，不要相信改之前的回读。
- 有偏移就按原计划整批重写一次 datetime，再校验；不要逐条手动修。

## 4. 校验：脚本比对，不靠抽查

用 `+record-list --format ndjson` 拉全量，然后：

- 按记录里文本列标注的时区，把 datetime 换算成本地时间，与文本列比对，输出不一致条数；
- 按日期聚合条数，核对市场周末跳过是否符合预期（例如阿联酋周五周六应为其他市场之和）。

完成标准：不一致条数为 0，且每日条数与排期规则一致。任一不满足就继续修，不要说「已排好」。

## 5. 回复口径

给出每日条数、时段、跳过的日期及原因，例如「11-06 只有 6 条，阿联酋周五不发」。没有校验数字的完成声明不算完成。

## 6. 整表改结构：排序、日历列、时间说明列

用户提「按优先级排序 / 时间要能选日历 / 加一列时间说明」这类整表调整时，按下面走，别先试错子命令。

- 读全表用 `+record-list --format ndjson --output <path>`；`+record-search` 必须带 `--keyword`，不带就直接报错，不能当全量读用。
- 排序没有 `+view-update`。用 `+view-set-sort --view-id <id> --json '{"sort_config":[{"field":"优先级","desc":false}]}'`；单选列的取序按选项定义顺序（P0→P3 建选项时就按这个序建）。先 `+view-list` 确认视图 id 和 `_meta.sort` 当前值。
- 固定周期（W1–W3）和浮动周期（资料到位起 T+2~4 周）不能混在一列：日历列只放能落成具体日期的，浮动周期写进独立的「时间说明」文本列、日期留空。原文本列改名为「时间说明」再新增两个 datetime 列，不要覆盖用户已手改的值。
- date-only 的 datetime 传 epoch 毫秒，按 Asia/Shanghai（+8）换算当天 00:00；批量用 `+record-batch-update --json @file`，一次提交。
- W1 这类相对周期要先问或声明锚点日（例如「从 11/09 这个周一算 W1」），落成绝对日期后再写，并在回复里给出每条区间，方便用户核对平移。

完成标准：视图 sort 里能看到目标字段且方向正确，日期区间逐条列出，浮动周期条目的日期为空。
