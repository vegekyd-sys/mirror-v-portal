# 成片闪烁 / 卡顿 / 接点不连贯 诊断与修复

客户说「画面一闪一闪」「这段不连贯」「一动一顿」时用本流程。先量化，再归因，再修，最后用同一套指标复检。不靠肉眼争论。

## 步骤

### 1. 量化两个指标

逐帧平均亮度差（找闪）：

```bash
ffmpeg -v error -i out.mp4 -vf "signalstats,metadata=print:key=lavfi.signalstats.YAVG:file=luma.txt" -f null -
```

读 `luma.txt` 取每帧 `YAVG`，算相邻帧差值，列出 `|Δ|>3` 的帧号与时间点。成组的跳变就是闪。

重复帧（找卡）：

```bash
ffprobe -v error -select_streams v -show_entries frame=pkt_pts_time -of csv=p=0 \
  -f lavfi "movie=out.mp4,mpdecimate=hi=64*12:lo=64*5:frac=0.33" | wc -l
```

与总帧数相比，比值即重复率。>2% 说明有重定时或变速引入的重复帧。

完成判据：拿到「跳变点时间列表」和「重复帧百分比」两个数。

### 2. 四项归因（按命中顺序查）

1. **叠化帧数不足**：查剪辑参数里的 transition 长度。10–14 帧（0.35–0.45s）才叫叠化；3–4 帧是把两张不同画面硬贴，必然闪。跳变点若全部落在接点上，基本可定此因。
2. **全片统一变速**：为凑时长对每条素材套 0.86–0.88x 之类缓速，30fps 下每 7–8 帧复制一帧，运动就断。看重复率是否集中在运动段。
3. **源素材自身频闪**：对单条源片做同样的 YAVG 检测（`crop` 到画面主体区，取 2–3 秒），若 90 帧内有 >15 次 `|Δ|>3`，是灯光频闪或自动曝光在跳，属源问题。
4. **素材间曝光差过大**：比较各条源片平均亮度，差 >20 级时，统一套一组调色参数不够，接点两侧必须逐条对齐。

完成判据：每一条跳变都能指到四项之一，且给出命中该条的原始数值。

### 3. 修复

- 叠化恢复到 10–14 帧，且叠化前先把前后两镜曝光/白平衡对齐到同一均值，接点两侧亮度差压到 ≤8 级。
- 取消全片统一变速，用原生 1.0x；不足的时长从素材多余段补，不靠拉慢。
- 源频闪：先去闪；去不干净就换同段落另一条素材。
- 调色从「全片一套参数」改为「逐条匹配」，同批曝光与白平衡统一到同一目标值。

完成判据：出片前四项都已处置，且每项的处置方式可写进交付说明。

### 4. 复检门槛

- 接点单帧亮度跳变 ≤8
- 重复帧 <2%
- 无连续两帧以上、累计 >20 级的亮度跌落
- 接点前后各 3 帧内无黑场/白场（`blackdetect` 复核）

三条全过再发客户；任一不过继续修剪，不靠「看起来还行」放行。

## 失败模式

| 现象 | 实际原因 | 不要怎么做 |
|-|-|-|
| 接点闪一下 | 叠化帧数不足或被故意压缩 | 不要用「运动模糊叠化」当理由保留 3 帧 |
| 整段一顿一顿 | 全片统一缓速 | 不要靠提高码率或锐化掩盖 |
| 只有某条素材闪 | 源片灯光频闪 / 自动曝光 | 不要用全片加 LUT 掩盖 |
| 每换一次场景亮度跳一下 | 素材曝光差大 + 统一调色参数 | 不要只调对比度 |

## 报告口径

回复客户时给三样：跳变点时间戳、重复帧百分比、每条对应的原因与修法。先承认是制作环节问题，再给复检后的两个数，不解释成「素材本身的锅」。
