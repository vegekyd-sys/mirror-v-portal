# Log / 灰度素材还原

用户说「素材是灰度的，按 LUT 还原一下」时，先测再动手。多数情况下能救的是层次，不是颜色。

## 步骤

1. **查元数据，确认是不是真 Log。**
   `ffprobe -show_entries stream=pix_fmt,color_transfer,color_primaries,color_range:format_tags`
   若 `encoder=Lavf*`、`color_transfer=bt709`、无相机机型标签，说明文件已被重编码，相机 Log 标记已丢失。此时不能用「官方 LUT」名义交付，要在回复里说明只能用等效曲线，并请用户提供官方 `.cube`。
   完成判据：能明确说出「原片是什么 Log / 无法确认」。

2. **测灰阶，判断是不是窄动态范围。**
   抽一帧算 `p5 / p50 / p95`。典型 Log 素材集中在 110–200（约 80 级），正常 Rec709 素材一般跨 30–230。
   完成判据：拿到三个百分位数字，能判断需要展开多少。

3. **测饱和度，决定能不能「还原颜色」。**
   平均饱和度 <0.08 时，色度信息已基本不存在，LUT 只能还原对比与层次。此时必须先告知用户「还原后仍是中性灰」，不要交付后让对方以为做坏了。
   完成判据：给出饱和度均值，并明确说明可救/不可救的范围。

4. **自建 33³ cube，按实测范围展开。**
   映射区间取实测 `p5–p95`，输出取 `0.10–0.90`；曲线用 `0.75×线性 + 0.25×smoothstep`，饱和度补偿 ≤1.15（放大会把色度噪声一起放大）。
   ```python
   t = clip((y-LO)/(HI-LO),0,1); s = t*t*(3-2*t)
   y2 = 0.10 + 0.80*(0.75*t + 0.25*s)
   out = y2 + (rgb-y) * (y2/y) * 1.12
   ```
   完成判据：生成 `.cube`，`LUT_3D_SIZE 33`，首行 TITLE 可读。

5. **应用并做轻度降噪。**
   `-vf "lut3d=<cube>:interp=tetrahedral,hqdn3d=1.5:1.5:4:4"`，母版 `-crf 16 -preset slow -pix_fmt yuv420p`。
   完成判据：输出文件可解码、时长与原片一致。

6. **量化验收，不达标就调曲线重来。**
   | 指标 | 通过标准 |
   |-|-|
   | p5 | ≥15，且 clip<5 像素 <0.5% |
   | p95 | ≤235，且 clip>250 像素 <0.5% |
   | 饱和度 | 比原片有提升即可，不追求「变彩色」 |
   首版若出现 p5≤10 或 p95≥240，判为过猛，必须改曲线重出（实测过一次 p5=7/p95=240，天空出色带，作废）。
   完成判据：三项都在范围内，并保留一帧 before/after 对比图。

7. **交付前按渠道限额重编码。**
   飞书单文件上限 30MB；23 秒 1440p 母版约 44MB，用 `-crf 25 -preset slow` 可压到 12MB 左右。
   完成判据：文件 <28MB 且已成功发送，不靠改扩展名或分包糊弄。

8. **回复里写清三件事**：原片是否有 Log 元数据、还原动了什么（层次/对比/降噪）、没动什么（颜色），以及「有官方 .cube 可再跑一遍更准」。

## 边界

- 不替用户判断这条素材该不该用；若素材本身违反客户禁镜（雾霾、浓烟、竞品 logo），还原之后照样不合规，要单独提醒。
- 不把色彩标记改成 bt709 冒充「已还原」；不输出无损但超限的文件让用户自己压。
- 没有实测数据就不下结论，尤其不要说「已经还原成彩色」。
