# 剪映字幕与配音包

给客户交付「可直接导入剪映」的字幕 + 配音素材。用户说「剪映字幕」「SRT」「英文/多语配音」「花字花样」时使用。

## 交付物

1. `.srt` 字幕（时间码 + 目标语言，单行 ≤28 字符）
2. 与字幕对齐的配音 `.mp3`（整轨，从 0 秒开始）
3. `.docx` 样式说明：每条字幕对应的花字/动画与剪映操作

## 步骤

### 1. 定稿口播与时间窗

按目标时长写 6–8 条英文/目标语句，每条给出 start/end（例如 0.3–3.2、3.4–7.4）。字幕与配音共用同一组时间窗，先定窗再合成。

句长按每秒 2.0–2.7 个英文词估算；窗口 3.5–4 秒对应 7–10 个词。完成标准：每条句子在窗口内可自然读完，不跨窗。

### 2. 生成配音

优先 edge-tts；若返回 403（WSServerHandshakeError），改用 gTTS：

```bash
python3 -m venv /tmp/gttsenv
/tmp/gttsenv/bin/pip install -q gtts
```

每行单独生成，不要整段生成。完成标准：每行一个 mp3，可被 ffprobe 读出时长。

备选顺序：edge-tts → gTTS（venv）。Volcano TTS 2.0 的英文 speaker 与 seed-tts-2.0 资源不匹配，报 55000000，不要在这条链上重试。

### 3. 对齐时间窗

用 ffprobe 测每行时长；超过 `end-start-0.1` 时用 `atempo=d/window`（上限 1.35）压缩，再测一次。

用 ffmpeg 按行延迟混音：

```bash
[0:a]aresample=44100,adelay=300|300[a0]; ... ;
amix=inputs=N:normalize=0,apad=pad_dur=1,atrim=0:TOTAL[aout]
```

输出 44.1k 单声道 mp3。完成标准：ffprobe 总时长等于目标时长（±0.1s），语音不越界。

### 4. 写 SRT

用同一组 start/end 写 SRT，序号连续，逗号毫秒格式。完成标准：条数与口播行数一致，时间码递增、不重叠。

### 5. 做花样说明

SRT 本身不携带样式，花字必须由剪映导入后逐条套用。用 docx 表格给出：序号、时间、英文字幕、中文对照、花样、剪映操作。

每条用不同处理（大字钩子/打字机/三词分屏/双色分屏/底部滑入/荧光笔/品牌条），并写明具体操作（花字类型、入场动画、贴纸、字号）。完成标准：7 条字幕对应 7 种不重复的处理，颜色不超过两种主色。

### 6. 交付到飞书

飞书一次只能发一个媒体附件，且 `.srt` 会被拒（path-not-allowed / unknown）。做法：

1. 把 srt + mp3 + docx 打成一个 zip（用 python zipfile，环境可能没有 `zip` 命令）
2. 先发 zip，附一句文件说明
3. 再把 mp3 单独作为 audio 发一次，方便对方直接试听

完成标准：zip 发送成功且回执有 media part；mp3 单独发送成功。

## 陷阱

- 不要把「样式」写进 SRT 就宣称已完成；剪映不读 ASS/SSA 样式。
- 不要整段合成后再硬切对齐，逐行生成 + adelay 才可控。
- 不要在同一句里塞两种语言；字幕语言与配音语言一致。
- 画面没发生的动作不要写进字幕。

## 验收

- SRT 可被解析，7 条时间码连续
- mp3 时长 = 目标时长，逐行不越窗
- docx 能打开，表格 7 行齐全
- 飞书 zip 与 mp3 均有成功回执
