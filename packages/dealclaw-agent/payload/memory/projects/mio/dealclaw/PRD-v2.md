## 一、产品定义

### 1.1 一句话

DealClaw 是 AI 驱动的 B2B 外贸销售智能体，帮中国工厂出海找买家、写开发信、自动跟进——越用越聪明。

### 1.2 不是什么

- 不是 CRM
- 不是传统 SaaS 工具（不是搜索框 → 返回列表）
- 不是单向自动化工具

### 1.3 核心价值

```
传统外贸销售: 1 个销售 = 同时管 10 个买家
DealClaw:   1 个销售 + AI = 同时管 50 个买家，且越做越准
```

### 1.4 产品形态

用户跟 V（AI 外贸顾问）在飞书里对话。V 在后台调度 20 个引擎完成搜索、画像、开发信、自动回复、知识库管理。用户只说"帮我找德国微逆买家"，V 就把结果推回来。

```
用户飞书消息 → V 判断意图 → 调引擎 → 回结果
                ↑
         画像反馈 → 下次更准
```

## 二、目标用户

### 2.1 核心用户

| 角色 | 场景 | 核心需求 |
|------|------|------|
| 外贸销售 | 日常找买家、发邮件、跟进回复 | 一句话搜买家、自动生成开发信、自动回复简单询盘 |
| 企业老板 | 看全局漏斗、管销售绩效 | 知道谁在干活、线索转化怎么样、物料缺什么 |
| 运营/产品经理 | 管知识库、补物料、看数据 | 产品和竞品信息结构化、买家反馈可追溯 |

### 2.2 用户画像（以 Solarunis 为例）

```
角色: 微逆出口销售
痛点: 不知道欧洲哪些安装商需要微逆，写了开发信不回复
使用 DealClaw 后:
  1. "找德国微逆买家" → 5 条精准线索
  2. 系统自动生成开发信（含产品目录链接）
  3. 买家回复 → IQ 自动跟 → 转人工
  4. 画像从 v1 涨到 v5，搜索结果越来越准
```

## 三、核心功能

### 3.1 功能全景

```
DealClaw
├── 🔍 买家搜索      搜买家 + 去重 + 画像重排序 + 线索入库
├── ✉️ 开发信生成    多语言 + 多渠道(Email/WA) + 物料自动附加
├── 🤖 询盘自动处理   意图识别 → 状态迁移 → 自动回复/人工断点
├── 🏢 企业知识库     三层架构(首页/主题页/资料层)
├── 📊 数据看板       漏斗 + 每日早报 + 审计日志
├── 🧠 买家画像       批量导入 + 实时标注 + IQ自适应 → 越用越准
└── 🔧 系统运维       健康检查 + 熔断降级 + 错误日志
```

### 3.2 核心链路

```
CBIE企业画像 → 搜索买家 → 开发信 → GS/FD/WA发送
                ↓ 回复
           IQ处理 → 自动回复 / 人工断点
                ↓
           标注反馈 → 买家画像进化 → 下次搜索更准
                ↓
           KB交互记忆 → Evolution进化建议 → 知识库文档更新
```

## 四、用户交互

### 4.1 飞书消息即界面

用户不打开任何外部工具。在飞书私聊或群里跟 V 对话：

| 用户说 | V 做什么 | 回复示例 |
|------|------|------|
| "帮我找德国微逆买家" | 搜索 + 画像重排序 | "找到 5 家。跟你历史客户最像的是 Munich Energy" |
| "看看知识库" | 拉取 KB 摘要 | "7 款产品，5/7 物料就绪，画像 v3。缺样品和视频。" |
| "更新知识库" | 重新发布全部飞书文档 | "好了，首页更新了" + 链接 |
| "今天怎么样" | 早报 | 漏斗 + 发送统计 + 进化建议 |
| "不发了，退订这个" | 写入退订记录 | "好" |

### 4.2 飞书文档 = 知识库

每家企业拥有独立三层飞书知识库：

- 第一层首页：一屏看懂企业全貌（V的判断 + 就绪度 + 机会）
- 第二层主题页：6 份深度文档（产品/市场/买家/销售/展会/企业）
- 第三层资料层：多维表格 + 文件索引 + 版本记录

## 六、安全与权限

### 6.1 企业隔离

每个企业的数据物理隔离。A 企业看不到 B 企业的买家、画像、知识库。

### 6.2 权限模型

| | 老板 | 销售 |
|------|:---:|:---:|
| 知识库首页 | ✅ | ✅ |
| 业务主题页 | ✅ | ✅ |
| 数据与资料 | ✅ 全量 | ✅ 仅自己的 |
| 买家搜索 | ✅ 全企业 | ✅ 自己的线索 |

### 6.3 合规

- 开发信自动附带 GDPR 隐私声明 (EN/PT/ES)
- 退订永久阻断，全渠道生效
- 买家数据最小化存储
- 第三方供应商透明记录

## 六-B、A/B 测试体系

### B.1 测试原则

DealClaw 的 A/B 测试不是传统 SaaS 的流量分割（样本量太小），而是**时间序贯对比 + 自动收敛**。

- **样本量**: 每个企业通常只有 10-50 个活跃买家，不做 50/50 分割
- **周期**: 按周切换变体，对比前后表现
- **收敛**: 统计显著差异后自动锁定优胜方，停掉劣化方
- **安全**: 退订率突增立即回滚到基线

### B.2 四类测试场景

| 场景 | 变体A（基线） | 变体B（实验） | 测什么 |
|------|------|------|------|
| 邮件主题 | 默认模板标题 | 新标题 | 打开率 |
| 邮件正文 | 默认话术 | 简短版/本地化版 | 回复率 |
| IQ 自动回复 | 通用模版 | 带物料链接的回复 | IQ 推进率 |
| 搜索排序 | CDP 原始排序 | Persona 重排序 | 标注"我的买家"率 |

### B.3 测试执行流程

```
第1周: 全量使用基线A，收集基准数据
第2周: 随机 50% 切到变体B，另一半继续A
第3周: 比较结果 → 显著则锁定，否则继续
第4周: 如未收敛，全量回到A，标记B为"无显著差异"
```

对 B2B 小样本场景，不做实时 A/B 分流。同一买家不会在不同时间收到不同版本的邮件。

### B.4 测量与判定

| 指标 | 数据源 | 判定条件 |
|------|------|------|
| 打开率 | send_log opened/delivered | B > A 且样本≥10 |
| 回复率 | send_log replied/delivered | B > A 且≥3封回复 |
| 退订率 | send_log unsubscribed/sent | B > A ×1.5 → 立即回滚 |
| IQ 推进率 | leads iq_stage 提升 | B > A 且≥5次处理 |

自动决策:
- 退订异常 → 秒级回滚
- 连续2周优胜 → 自动锁定
- 4周无结论 → 人工判断

### B.5 测试引擎 dc_abtest.py

```bash
# 发起测试
python3 dc_abtest.py start email_subject solarunis.com \
  --variant "简短版标题" --baseline "默认标题"

# 查看状态
python3 dc_abtest.py status solarunis.com
# → 变体B打开率31%(5/16) vs 基线13%(2/15)，建议锁定B

# 锁定
python3 dc_abtest.py lock solarunis.com
# → Copy 引擎自动切换默认模板
```

### B.6 与闭环的关系

A/B 测试不是独立功能——测试结果直接进入进化回路:
- 锁定优胜 → Copy 引擎自动切换模板
- 写入 Evolution → 早报"进化建议"显示
- 企业画像偏好标记 → Persona 版本+1

用户不需要知道测试在跑。他只看到下周的回复率比这周高了。
