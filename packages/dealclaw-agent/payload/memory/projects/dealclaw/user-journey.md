## 1. 企业入场（Onboarding）

### 1.1 丢 URL 或 产品目录 PDF

```
用户: "分析下这家" / 直接发URL / 发PDF
  → V 后台跑 CBIE 解析
    → 出摘要卡片:

┌─────────────────────────────┐
│ 🔖 德粘堡实业（DENIBO）      │
│ 2002年成立，佛山，年产10亿㎡  │
│ BOPP胶带·文具胶带·印刷定制    │
│ 出口：东南亚·欧洲·美洲·中东    │
│ ─────────────────────────── │
│ 看起来是成熟出口制造商。      │
│ [💬 聊聊出海] [📊 市场洞察]   │
└─────────────────────────────┘
```

### 1.2 聊出海 — 顾问式追问

点"聊聊出海" → V 像顾问一样追问关键信息：

```
V: 你们出海主要卖什么产品？去哪些国家？
   有没有什么认证？有没有不能卖的地区？
```

用户自然回答，V 提取关键约束：
- 产品聚焦（比如渤程：只卖离心机）
- 市场排除（比如无 CE/FDA，排除欧美日）
- 重点区域（比如俄+东南亚）

**不做的事**：不让用户填表、不丢 20 行画像

## 2. 找买家（Lead Acquisition）

### 2.1 搜索

```
用户: "帮我找 10 个印尼胶带买家"
  → V 并行搜索（公网/B2B/黄页）
    → 过滤匹配度（产品·市场·资质）
      → 10条一批展示
```

### 2.2 线索展示 — ≤5条：卡片

每条一张窄卡（Feishu Cards v2）：

```
┌─────────────────────────────────┐
│ PT Indo Packaging Sejahtera     │
│ 🔗 indopack.co.id               │
│ 🇮🇩 印尼 · 公网搜索               │
│ 包装耗材 · 进口分销 · BOPP胶带    │
│ [✅ 我的]  [❌ 不是]  [📋 已有]   │
└─────────────────────────────────┘
```

### 2.3 线索展示 — 6-30条：10条一批文字列表

```
🔍 为德粘堡找到 10 条印尼买家（第1批）

① PT Indo Packaging        https://indopack.co.id
   🇮🇩 印尼 · 公网搜索   包装耗材 · 进口分销 · BOPP胶带

② CV Sumber Packindo       https://sumberpack.co.id
   🇮🇩 印尼 · 公网搜索   胶带分销 · 文具包装 · 电商物流

③ PT Mega Tape             https://megatape.co.id
   🇮🇩 印尼 · B2B平台     BOPP制造商 · 工业胶带 · OEM

...

回复格式：「1-3,6我的 / 4,7不是 / 5,8已有」
```

每批 10 条，用户标完再出下批。V 解析自然语言入库。

### 2.4 反馈反哺

| 标注 | 存储 | 反哺 |
|------|------|------|
| ✅ 我的 | `leads/{uid}-qualified.md` | 提取国家/行业特征，强化匹配 |
| ❌ 不是 | `leads/{uid}-rejected.md` | 追问原因，更新排除规则 |
| 📋 已有 | `leads/{uid}-existing.md` | 加入已有池，不再推荐 |

### 2.5 联系人验证（待数据库接入）

公网搜索拿不到具体联系人。info@/sales@ 只能兜底。

等米奥数据库 + 海关数据接入后：
- 公司名反查海关提单 → 找进口记录和联系人
- 展会数据交叉匹配 → 历史洽谈记录
- 多源交叉验证联系人是否在职/是否决策人

## 3. 写内容（Content Generation）

### 3.1 邮件

**展前邀约**（2轮）：展前14天 + 展前3天

**展后跟进**（24h内）：基于意图分析生成个性化邮件

**首次触达**：自我介绍 + 轻量提问，不提价格/不推销

### 3.2 WhatsApp 首次触达

**风控规则**（参考 `channel-rules/whatsapp-first-touch.md`）：

| ❌ 不能做 | ✅ 正确做法 |
|-----------|-----------|
| 首条带链接 | 纯文本自我介绍 |
| 提价格/折扣 | 问句结尾，求回复 |
| 批量模板文案 | 每条个性化 |
| 新号一天 50+ 触达 | 控制量，分批 |

三步走：首触达 → 对方回复 → 再发资料 → 第三次推邀约

### 3.3 多语言本地化

不是翻译，是按国家/渠道改写：

- 德语 → 正式 `Sehr geehrte`，不提价格
- 印尼语 → WhatsApp 短句风格
- 俄语 → 正式 + 俄语资料
- 渠道适配：邮件 / WhatsApp / LinkedIn 各出不同版

## 4. 展会全链路（Exhibition）

### 4.1 展前：邀约买家

```
用户: "我要参加 XX 展会，帮我邀请买家"
  → V 先问展会信息（名称/地点/日期/展位号/主推产品）
    → 补齐后 → 筛选匹配买家 → 生成邀约邮件/WhatsApp
      → 两轮触达：展前14天 + 展前3天
```

参考: `email-templates/exhibition-invitation-2-round.md`

### 4.2 展中：现场线索处理

```
用户在展位上传:
  - 名片照片 → OCR 提取公司/姓名/职位/邮箱
  - 洽谈录音 → ASR 转写
  - 随手备注 → 文本记录
  → V 自动匹配名片↔录音
    → 判断意向: 高/中/低
      → 提取需求/采购量/痛点/认证要求
        → 生成当天线索小结
```

**隐私门**：涉及联系人邮箱/电话/录音 → 先确认是否获得对方同意

参考: `workflows/exhibition-lead-processing.md`、`DC-EL Skill`

### 4.3 展后24小时：跟进

```
  → 基于意图分析生成个性化 follow-up 邮件
    → 报价/资料/样品跟进提醒
      → 高意向客户优先触达
        → CRM 更新内容
          → 设置下次跟进时间
```

### 4.4 展后持续：CRM 推进

```
  → 哪些客户没回 → 二次触达时间
    → 哪些客户要报价 → 提醒发送
      → 哪些客户只是逛展 → 不追
        → 老板日报：见了多少人/几个高意向/预计机会
```

## 10. 交互设计原则

> 来源：飞书文档 · 格格 · v1.6/v1.9

### 设计纲领

V 不是一个界面，是一个有经验的同事。三条底层逻辑：
1. **不等用户问** — 主动指出缺信息、主动给下一步
2. **不给用户压力** — 选择题不是开放题、提醒不追问
3. **像人在协作** — 先给判断再给细节、边做边同步

### 交互形式分布

| 形式 | 占比 | 用途 |
|------|------|------|
| 💬 聊天气泡 | 80%+ | 对话确认、判断摘要、纠偏引导、提醒通知 |
| 📄 飞书文档 | 深度内容 | CBIE 画像、MI 市场洞察、OS 策略全案、EL 展会处理 |
| 📊 多维表格 | 结构化 | KB 知识库索引、LS 线索列表（需筛选/排序/批量操作） |
| 🃏 飞书卡片 | 仅2处 | CBIE<60分补全提示、EL GDPR隐私门 |

**气泡给判断，文档给细节。**

### Onboarding 流程

- Phase1（2秒内）：确认收到
- Phase2（20秒内）：判断摘要 + 主动纠偏（≤3个pending字段）
- Phase3（30-60秒）：生成文档 → 逐条确认修正 → 用户修改优先于AI保留

### 纠偏 + 偏好晋升

- PRC 检查 MEMORY.md → 不存在则自动创建四区结构 → 执行纠正
- 同一企业内 3 次排除同一类型 → 晋升为偏好
- 已有画像 → 提示覆盖或查看旧报告
- 纠偏全部跳过 → 直接 Phase3
- 评分<60分 → 弹补全提示卡片（继续/补充二选一）

## 11. 已知风险

| 风险 | 影响 | 优先级 |
|------|------|:---:|
| 公网搜索买家信息不真实/过时 | 联系后才发现公司不存在 | 🔴 |
| 无联系人信息 → info@/sales@ 打开率低 | 找了一堆买家但触达无效 | 🔴 |
| 内容生成后无法真实发送 | 用户需手动复制 → 体验断层 | 🔴 |
| 飞书卡片 v2 callback 在群聊中未验证 | 用户点按钮 V 收不到 | 🟡 |
| OCR/ASR 链路未真实验证 | 展会场景全是纸上设计 | 🟡 |
| 图片型 PDF 解析不完整 | CBIE 画像缺失 → 后续全链偏 | 🟡 |
| 多语言内容无母语 QA | 俄语/阿语内容可能有误 | 🟡 |
| 用户跳过追问直接下指令 | V 带着信息缺口继续工作 | 🟢 |
| 自然语言标注解析边界 case | 标了但 V 理解错 → 误伤/漏标 | 🟢 |

### 接入前关键路径

1. 🔴 验证飞书 v2 卡片 callback（线索标注核心交互）
2. 🔴 跑通 OCR+ASR 真实链路（展会 killer feature）
3. 🟡 补多语言模板库（至少印尼/俄）
4. 🟡 补各国 WhatsApp 风控规则
5. 🟡 实现「标"不是"→追问原因」（偏好闭环关键缺口）
