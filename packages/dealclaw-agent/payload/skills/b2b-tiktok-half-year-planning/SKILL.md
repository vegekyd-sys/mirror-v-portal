# B2B TikTok 半年包矩阵策划案 Skill

## 触发条件

用户发送「VIP客户需求确认表」（半年包），要求输出策划案。

## 前置步骤

1. 读取需求表内容 → 提取关键字段 → 缺失标注「待客户补充」

## 输出

飞书文档，标题「{客户公司名称} — 海外短视频矩阵策划案」。

---

## 内容红线（最高优先级）

### 画面约束
所有视频画面必须是工厂实拍。禁止动画、Motion Graphics、图表动画、3D渲染、特效合成、手绘插画等非实拍视觉元素。允许实拍画面上叠加文字标注/卡片+AI配音+动态字幕。

### 转化路径约束
**不能在 Bio 挂联系方式。所有转化引导只能指向评论区留言或后台私信。**
- ❌ Bio挂WhatsApp/邮箱/网站/电话
- ❌ 视频中直接显示联系方式
- ✅ 视频末尾/评论区引导「Comment below for inquiry」「DM us for details」
- ✅ 账号描述引导「Send DM for quotation」

---

## 一、项目背景

1.1 公司概况 / 1.2 产品与产能 / 1.3 核心竞争优势 / 1.4 市场切入逻辑 / 1.5 竞争对标

## 二、目标客户画像

2.1 核心买家群像 / 2.2 买家核心顾虑与常见问题（痛点+FAQ合并表）

## 三、矩阵账号架构

### 账号层级判断原则

按「地区流量池 + 语言受众池」判断。同语≥3可拆三层；混语言账号不硬拆同一漏斗；同语=2拆双号闭环；同语=1用综合号。

### 章节

3.1 账号总表 / 3.2 账号分层与职能 / 3.3 跨市场分发策略（YT仅TK短视频同步分发） / 3.4 发布节奏 / 3.5 流量词Hashtag

## 四、内容策略

**开头**：画面约束+转化路径约束+一句话策略。

- **4.1**：六模型表格。参考视频必须 web_search 搜真实 TikTok URL，禁止假 URL。
- **4.2**：五场景选题库。全部实拍描述，禁止「动画」「图表」等非实拍方式。
- **4.3**：两阶段内容配比（策略描述不用百分比）
- **4.4**：全周期内容规划表格。投放时段区分 M2-M3/M4-M6。画面构成列全部实拍描述。
- **4.6**：P0/P1/P2 三级拍摄清单

## 五、半年内容排期

5.1 半年阶段划分：M1→M2-M3→M3末→M4-M6→M6末

## 六、长效转化体系

- **6.1 B2B内容转化漏斗**：层层引导至评论区/私信
- **6.2 内容资产沉淀与复用**：YT与TK同步分发相同短视频
- **6.3 询盘承接与跟进建议**：24h内响应评论区/私信

> 所有转化路径描述中禁止出现「Bio挂联系方式」「Bio挂WhatsApp/邮箱/网站」等表述。统一用「评论区引导留言」「引导后台私信」「Comment/DM for inquiry」替代。

---

## 编辑原则

- 数据全来自需求表
- 账号层级按地区流量池+语言受众池判断
- 产品名/工艺/卖点必须来自需求表
- YT 不做品牌沉淀，仅短视频同步分发
- 4.1 参考视频必须真实 TikTok URL
- 4.4 投放时段区分 M2-M3/M4-M6
- 全文档画面描述全部实拍，无动画/图表/3D/特效
- **全文档无「Bio挂联系方式」描述，统一用「评论区留言」「后台私信/DM」**

## Verification Gate（生成后必检）

文档生成后，执行以下验证：

1. `lark-cli docs +fetch --scope outline` → 验证六章结构完整
2. 确认关键表格（账号总表、选题库、拍摄清单）完整无截断
3. 全文搜索 "Bio""WhatsApp""邮箱""网站" → 确保无违禁联系方式（仅评论区/私信/DM）
4. 全文搜索 "动画""3D""图表""流程图" → 确保无违规视觉元素
5. 如有 web_search 数据 → 验证所有 URL 可访问、数据有来源标注

## Self-QC Checklist

生成后逐项自检，全部通过才能创建审核：

- [ ] 六章结构完整，每章有实质内容（非空）
- [ ] 数据全来自需求表，无编造
- [ ] 账号层级符合规则（同语≥3三层/同语=2双号/同语=1综合）
- [ ] 无真人出镜
- [ ] 全实拍无动画/图表/3D
- [ ] 4.4 投放时段两阶段区分（M2-M3/M4-M6）
- [ ] 4.1 参考视频全部真实 TikTok URL
- [ ] YT 无品牌沉淀描述
- [ ] 全文无「Bio挂联系方式」，均为「评论区/私信/DM」
- [ ] 文档面向运营/销售可读，无技术术语

**QC 不通过 → 重试最多 2 次 → 仍不通过 → 写阻塞原因。**
**QC 通过 → 创建 Base 审核记录。**

## Failure Modes

| 情境 | 处理 |
|---|---|
| 需求表数据不足 | 标注「待客户补充」，不编造 |
| web_search 不可用 | 跳过市场数据，标注"待补充" |
| 账号层级判断不清 | 按保守规则（同语=1用综合号），不硬拆分层 |
| 文档编辑权限不足 | 告知用户，不继续修改 |
| 出现违禁词汇 | 全文替换后重新 QC |
