# DC-OBS: 海外采购商搜索

> DealClaw Skill | 版本: v1.0 | 创建: 2026-07-09
> 隶属 DealClaw 体系，复用 DC-CBIE（企业画像）+ DC-LS（买家搜索匹配引擎）+ DC-KB（多维表格存储）

---

## 触发条件（自动）

用户消息中出现以下任一关键词组合时，自动触发本 Skill：

| 触发词 | 示例 |
|--------|------|
| 海外采购商 | 「帮我找海外采购商」「有没有海外采购商推荐」 |
| 买家搜索 | 「买家搜索」「做一次买家搜索」「帮我搜买家」 |
| 找买家 | 「找几个欧洲买家」「找买家」「帮我找下游买家」 |
| 找客户 | 「找海外客户」「找几个潜在客户」 |

**不触发的情况：**
- 用户已经进入 DC-CBIE 流程中（发 URL / 说「分析这个公司」）→ 走 DC-CBIE
- 用户说「查看知识库」「打开知识库」→ 走 DC-KB
- 用户说「市场洞察」「分析市场」→ 走 DC-MI
- 用户说「确认/修改画像」→ 走 DC-PRC

---

## 一、Skill 定位

DC-OBS 是 DealClaw 体系中「买家搜索」的自动入口。它不做新的搜索逻辑——它是一个路由+存储层：

```
用户说"找买家"
 ↓
DC-OBS 自动触发
 ↓
检查画像是否存在？
 ├─ 不存在 → 引导创建（DC-CBIE）
 └─ 存在 → 加载画像 + 偏好 → 转发 DC-LS 引擎
 ↓
DC-LS 执行搜索 → 结果存入多维表格
 ↓
DC-OBS 输出气泡摘要 + 表格链接
```

**核心原则：OBS 不做搜索，只做路由 + 存储。搜索逻辑全部在 DC-LS。**

## 二、前置检查

### 2.1 画像检查

| 条件 | 行为 |
|------|------|
| 当前企业画像已确认（≥80%填充） | ✅ 直接进入搜索 |
| 画像存在但 <80% | ⚠️ 询问是否先补全画像 |
| 无画像 | ❌ 引导创建：「先给我一个企业官网，我帮你建画像，然后才能精准搜买家」 |

### 2.2 偏好加载

从 DC-PRC 的用户偏好中加载当前用户的搜索偏好（国家/行业/产品/排除规则）。

### 2.3 信息补全

如果用户只说「找买家」未指定国家/行业/产品，按 DC-LS Step 3 规则补全。

---

## 三、搜索执行（委托 DC-LS）

确定搜索条件后，将以下参数传递给 DC-LS 引擎：

| 参数 | 来源 |
|------|------|
| 企业画像 | DC-CBIE / DC-PRC 已确认画像 |
| 目标国家 | 用户输入 or 画像目标市场 or 偏好 |
| 买家类型 | 用户输入 or 画像买家身份类别 |
| 产品线 | 用户输入 or 画像主营产品 |
| 搜索数量 | 用户指定数量（默认 5） |
| 用户偏好 | DC-PRC 当前用户偏好数据 |
| 去重数据 | 全局历史线索库 + 用户级历史 |

DC-LS 负责：搜索 → 去重 → 七维评分 → 排序。

---

## 四、多维表格存储

搜索结果确认后，写入飞书多维表格。**复用 DC-KB 的 bitable 操作经验。**

### 4.1 表格结构

| 列名 | 类型 | 说明 |
|------|------|------|
| 国家 | 单选 | 买家所在国家 |
| 行业 | 单选 | 买家所属行业 |
| 企业名 | 文本 | 买家企业名称 |
| 企业介绍 | 文本 | 一句话企业介绍（主营+规模+定位） |
| 官网 | 文本/URL | 买家官网链接 |
| 预计采购产品 | 文本 | 买方可采购的产品品类 |
| 预计年度采购规模 | 文本 | 预估年度采购量级（如「$50K–200K」「pending」） |

### 4.2 表格创建

- 首次搜索 → 创建新表格（表名：`[企业名] · 海外买家线索`）
- 后续搜索 → 追加到同一表格，按搜索条件筛选
- 表格权限 → 参考 DC-KB：`anyone_readable` + 管理员 可管理

## 五、输出

### 5.1 气泡摘要（搜索完成后）

```
📊 [国家] [行业] — [N] 条入库
[领跑企业] 领跑，[X] 推荐 [Y] 谨慎。[一句话判断]
🎯 [N] 条重点关注线索

📋 查看线索 →
```

### 5.2 多维表格链接

飞书多维表格链接。用户随时点开查看。

### 5.3 推荐理由（用户追问时）

复用 DC-LS Step 6 的推荐理由输出规则。不展示分数，只给判断。

## 六、与 DC-LS 的分工

| | DC-OBS | DC-LS |
|------|--------|-------|
| 触发 | 关键词自动触发 | DC-CBIE/PRC 流程中调用 |
| 做什么 | 路由 + 存储 | 搜索 + 评分 |
| 画像 | 检查画像是否存在 | 加载已确认画像 |
| 搜索 | 委托 DC-LS | 实际执行搜索 |
| 存储 | 多维表格 | — |
| 输出 | 气泡 + 表格链接 | 气泡 + 表格链接（同） |

**OBS 是 DC-LS 的外层包装——加了自动触发、画像前置检查、多维表格持久化。搜索核心逻辑不重复。**

## 七、交互示例

### 首次使用（无画像）

```
用户：「帮我找海外采购商」

V：「先给我一个企业官网——我帮你建画像，
 知道你是谁、卖什么、卖给谁，才能精准搜买家。」
```

### 有画像、信息完整

```
用户：「找 5 个德国泵阀买家」

V：「德国泵阀买家，用海诺的泵壳产品线来搜～」
 [搜索中...]

V：「📊 德国泵阀 — 5 条入库
 KSB 领跑，3 推荐 2 谨慎。产品匹配整体偏高。
 🎯 1 条重点关注线索

 📋 查看线索 → [多维表格链接]」
```

### 有画像、信息不足

```
用户：「帮我找买家」

V：「先帮我确认一下——」
 「要找哪个国家的？」
 [意大利] [德国] [荷兰] [东南亚] [不限]
```

## 八、技术实现备注

### 飞书 Bitable API

| 操作 | 说明 |
|------|------|
| 创建表格 | 复用 DC-KB 已验证的 bitable 创建流程 |
| 写入数据 | 批量写入搜索结果 |
| 权限 | `anyone_readable` + 管理员 可管理 |

### 去重存储

去重基于多维表格中已有数据（`企业名` + `官网` 双键去重）。搜索前查询已有线索，过滤重复后展示。
