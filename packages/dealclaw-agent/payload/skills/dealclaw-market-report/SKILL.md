# 外贸市场决策与选品 HTML 报告

## 触发与主动引导（灵活，不死等关键词）

**识别到用户有「看市场」的意愿就主动引导，不要死等用户说「报告/分析」。**

- 用户提到「产品 + 国家/市场」组合（如「巴西减速机好卖吗」「美国咖啡机市场怎么样」「想进墨西哥」），即使没说「报告/分析」，也是看市场意愿 → 主动提出：「我可以帮你做一份 {国家}{产品} 的市场报告——市场规模、竞争、关税、进入建议，要吗？」
- 用户确认后生成；拒绝就停，不硬推。
- 只有产品没国家、或只有国家没产品时，问缺的那个，别猜。

## 输入与输出

必填：`category`（产品品类）、`country`（单一目标国家或市场）。

默认输出：`[品类]_[国家]_市场决策与开拓报告.html`。使用简体中文，保留必要的当地语言名称、搜索词和法规原名；金额同时显示当地货币与 USD，并标注汇率日期。

若用户输入多个国家，为每个国家执行一次完整研究并生成独立 HTML 文件。不要把多个国家拼进同一份报告。

### 🚨 交付强制规则

**最终交付物 = HTML 文件 + 核心摘要卡片，两个缺一不可。**

1. `write` → 存 `.html` 到 workspace
2. `message.send` + `filePath` → 发 HTML 文件
3. `message.send` → 发核心摘要（用飞书卡片或文字），必须在同一条消息里或紧跟在文件后面

**核心摘要格式（必须包含）：**

```
总体建议：🟢条件进入 / 🟡谨慎进入 / 🔴暂缓
| 维度 | 判断 |
|---|---|
| TAM | $XXXM（2026估），CAGR X% |
| 最佳品类 | #1 XX（XX分）→ #2 XX → #3 XX |
| 进入路径 | XX → XX → XX |
| 盈亏平衡 | 月销XX件 |
| 首年目标 | $X-XM |
| 关键洞察 | 一句话核心判断 |
```

- ✅ 正确：发 HTML 文件 + 附上表格式核心摘要
- ❌ 错误：只发文件没有摘要
- ❌ 错误：只发摘要没有文件
- ❌ 错误："报告已生成：work/xxx-report.html" → 用户收不到文件
- ❌ 错误：用 `MEDIA:` 行发 HTML → MEDIA 只支持图片/音频/视频，不识别 .html 文档，附件会被丢弃；文档一律用 `message.send` + `filePath`

## 工具边界

- 不安装、不要求、不调用 Exa MCP。
- 使用当前可用的互联网浏览/搜索能力、政府与海关网站、官方统计和贸易数据库、当地平台前台、企业官网、经销商与公开项目资料。
- 没有联网能力时，仅使用用户提供或本地已有资料，并将时效性和数据缺口写入报告；不得用记忆补造现行价格、税率、法规或排名。

## 数据源 API Key

研究可用的官方贸易数据接口（用于「执行流程」第 2、4 步的贸易流/市场规模证据，对应 `references/data-evidence.md` 证据等级 C）：

| 数据源 | API Key | 用途 |
|---|---|---|
| 联合国数据（UN Comtrade） | 环境变量 `UN_COMTRADE_API_KEY` | 各国进出口额 / 贸易流 |
| WTO 数据 | 环境变量 `WTO_API_KEY` | 全球贸易 / 关税 / 政策数据 |

- Key 存于环境变量（`UN_COMTRADE_API_KEY` / `WTO_API_KEY`，定义在 `work/mio-api/.env`），取数时读环境变量，不硬编码进本文件。
- 优先用这两个官方源交叉验证市场规模与增长；Key 仅用于取数，不写进报告正文，报告里只标来源与链接。

## 执行流程

0. **起卡。** 确认生成后，第一步起实时进度卡（`work/mio-api/cards/market_report_card.py`），原地更新进度、不在中途另发文字；研究完成后终态绿卡附报告链接。

1. **锁定国家与品类**：定义当地语言/英语/中文名称、品类树、用途、排除项、买家类型和监管属性。
2. **建立国家证据账本**：按 `references/data-evidence.md` 收集并记录国家、日期、单位、口径、来源和证据等级。
3. **判断国家环境**：只保留影响该品类进入决策的人口/产业、消费、贸易、渠道、支付、物流和文化变量。
4. **估算市场**：使用可用的自上而下、自下而上、贸易/平台代理交叉验证 TAM/SAM/SOM；证据不足时给可审计代理池，不伪造精确规模。
5. **研究需求与竞争**：分析趋势、季节性、地区、买家、采购链、价格带、活跃企业、渠道、VOC 和未满足需求。
6. **先做合规闸门**：核验进口、HS 候选、税费、认证、标签、责任主体、知识产权、物流、安装和售后。
7. **建立选品池并评分**：生成 10–20 个子类/产品形态，使用 `references/scoring-model.md`；硬门槛优先于分数。
8. **形成进入方案**：给出首发组合、渠道伙伴、定位、落地成本、三种经济情景、90天路线图和 Kill Criteria。
9. **生成 HTML**：复制 `assets/report-shell.html` 的视觉体系，按 `references/report-template.md` 组织内容，写入完整可读正文和真实来源链接。
10. **检查交付物**：确认文件可离线打开、无占位符、无 Exa 依赖、国家未串线、核心数字可追溯、打印不超过20页。

## 实时进度卡（硬交付物）

市场报告是长任务，实时进度卡是交付物的一部分、不是可选项，不得只用一句「预计耗时」替代。用共享运行时 `work/mio-api/cards/market_report_card.py` 的 `MarketReportCard` 起卡并原地更新，不在中途另发文字重复结果。

四节点：

| 节点 | 方法 | 状态文案 |
|------|------|----------|
| 步骤 1/4 | `card.scoping()` | 已确认国家、品类与证据口径 |
| 步骤 2/4 | `card.researching()` | 市场规模 / 需求竞争 / 合规闸门核查中 |
| 步骤 3/4 | `card.scoring()` | 选品池评分与进入方案制定中 |
| 步骤 4/4 | `card.rendering()` | HTML 生成与交付物检查中 |

终态：

- `done`：绿色完成卡，附「打开报告」链接（`finish_done(report_url=...)`）。
- `partial`：数据不足、报告中标注缺口的「部分完成」（`partial(report_url=...)`）。
- `failed`：生成失败（`fail()`）。
- `cancelled`：用户取消（`cancel()`）。
- `waiting_user`：缺国家/品类等关键输入（`waiting_user()`）。

卡片不显示内部评分权重、接口错误栈；不伪造百分比和预计完成时间。起卡身份与 find-buyers / 展后报告一致（共享运行时 `work/mio-api/cards/`）。

## 国家隔离规则

每份报告必须独立确定：当地搜索词、消费者/买家语言和品类叫法；当地货币、汇率、收入/采购能力和地区分布；当地电商、零售、批发、经销、工程或展会渠道；当地法规、标准、税制、贸易协定、标签和责任主体；当地竞争者、价格、促销、VOC、付款、物流和售后习惯；当地季节、节日、气候、采购周期和90天进入节奏。

跨国数据只能作为明确标注的代理或背景，不能直接进入该国市场规模、评分或 Go/No-Go 结论。

## 事实完整性

- 不编造市场规模、增长率、份额、排名、销量、价格、税率、认证或竞品信息。
- 决策关键数字附来源、发布日期/数据期、采集日、国家、单位和证据等级。
- 明确区分 `事实`、`估算`、`推断`、`管理假设`。
- 三种规模方法相差超过 2 倍时展示差异，禁止简单平均。
- 缺失评分权重超过40%时，不给总分和 Go 结论；显示"数据不足"。
- 平台样本不得无说明外推为全国市场；企业宣传不得当作市场份额。

## 行业自适应

- **B2C/电商**：强化平台需求、内容、价格、促销、评价、退货和平台集中度。
- **B2B工业品**：强化应用、买家、标准、RFQ周期、服务网络、备件和总拥有成本。
- **监管品**：把许可、注册、检测、标签和进口限制放在机会评分之前。
- **消耗品**：强化复购、保质期、补货、留存和渠道周转。
- **季节/时尚品**：强化趋势波动、变体、库存、退货和营销日历。
- **大件/易碎/安装品**：强化体积运费、破损、仓储、安装、维修和本地伙伴。

## HTML 交付标准

- 生成单文件、内联 CSS、默认不依赖外部字体/脚本/CDN；离线可读。
- 采用中国外贸企业熟悉的"结论先行—数据支撑—选品—渠道—执行"顺序。
- 使用深海军蓝主色、商务红强调、橙色风险、绿色机会；中文字体优先微软雅黑/苹方。
- 桌面端像咨询报告，移动端可阅读，打印为 A4；默认18页、硬上限20页（含封面与来源）。
- 每页一个核心决策；图表标注单位、币种、时间、地区和来源。无数据时显示缺口，不绘制假图。
- 完整视觉与页数规则见 `references/report-template.md`；基础结构与 CSS 使用 `assets/report-shell.html`。
