# DealClaw Buyer Profile

## 定位

找买家链路的中段：承接 `dealclaw-analyze-company` 输出的产品线清单，产出「买家分组」，供 `dealclaw-find-buyers` 按分组逐条执行搜索。

**本 skill 只做分析，不做搜索、不拉数据。**

## 触发

- 「找买家」链式调用时，作为 analyze-company 之后的第二跳（禁止跳过）
- 用户有多条产品线、或已有企业画像但买家类型不明确时
- 用户问「买家画像」「这几类买家一样吗」「该找哪类买家」时

## 输入

`dealclaw-analyze-company` 的结构化产品线清单（每个产品 + 材质/用途/定位）。

若用户直接给了产品清单（没走 analyze-company），同样处理，不强制先跑 analyze-company。

## 输出

买家分组结果，每组包含：
- 产品线（合并后的）
- 买家类型（经销商 / 进口商 / 零售商 / 终端机构）
- 关键信号（展会报名、买家等级、历史到展等，可后置到 find-buyers）
- 优先级建议

## 核心规则：按「买家类型」分组，不是按「产品数量」

**先分析、再出结论，禁止一刀切。**

1. 列出用户全部产品/品类。
2. 逐产品判断「谁买」→ 映射到买家类型。
3. **同一买家类型 → 合并成一条搜索；不同买家类型 → 拆开单独搜索。**
   - 例：护理床/升降床（医院设备经销商） vs 康复辅具拐杖助行器（移动辅具零售商）→ 买家不同，必须拆。
   - 例：办公家具（老板桌） + 人体工学（升降桌/椅）→ 都是办公家具经销商，合并。
4. 大多数场景下，一家公司的同类产品共享同一买家；只有买家类型变化才拆线。
5. 分组结果先跟用户确认（哪些合、哪些拆、优先级），确认后再交给 find-buyers。

## 交付格式

把分组结果简要列给用户确认，例如：

```
买家分组（按买家类型）：
- 组1 办公家具 + 人体工学 → 办公家具经销商/进口商（合并，1条搜索）
- 组2 护理床 → 医院设备经销商/医院（拆开）
- 组3 康复辅具（拐杖/助行器）→ 移动辅具/家护零售商（拆开）
优先级建议：组2 > 组3 > 组1
确认后按组逐条搜索。
```

## 边界

- 不搜索、不拉数据，只做产品 → 买家类型的映射和分组。
- 分组维度是买家类型，不是产品数量。
- 不确定某产品的买家类型时，问用户，不猜。
