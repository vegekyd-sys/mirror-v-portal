# dealclaw-ai-hunter · 企业线索池落库

> 复用 `dealclaw-buyer-leads-push` 的「企业线索池」Base（`企业名称｜企业线索池`，pool 布局：`线索池` + `评分明细` + `参展行为`）。schema 与写入脚本与 buyer-leads-push 完全一致，见 `dealclaw-buyer-leads-push/references/base-schema.md`。

## 落库时机

1. **推送时**：每条推送/入池的询盘买家，先 upsert 到 `线索池`（接口事实字段 + AI 评分字段），再渲染卡片发送。
2. **解锁后**：`detail` 调用成功（调用即扣 360 点）并交付明文卡片后，把该线索的解锁状态写回 `线索池`。

## 落库字段（`线索池` 主表）

- **接口事实字段**：`线索ID`、`买家公司名称`、`买家公司简介`、`买家国家`、`产品类别T1/T2`、`需求意向`、`关注产品`、`买家类型`、`买家特征`、`报名参展展会`、`需求时间`。
- **AI 字段**：`AI匹配分`、`AI原始分`、`反馈扣分`、`AI匹配等级`、`核心匹配通过`、`AI匹配理由`、`评分明细`（九维逐项分数+证据）、`线索明确MOQ`、`评分权重版本`（`v10-32-24-18-10-6-4-2-2-2`）、`企业画像版本`、`企业画像群ID`、`画像企业名称`、`运行上下文ID`、`AI处理时间`。
- **用户反馈字段**：`是否匹配`、`不匹配原因`、`反馈说明`、`反馈人`、`反馈时间`、`跟进状态`、`跟进备注`、`是否解锁`。
- **解锁系统字段**：`解锁人`、`解锁时间`、`解锁方式`、`解锁推送消息ID`。
- **系统字段**：`唯一去重键`、`飞书群ID`、`首次入池时间`、`最近更新时间`、`首次推送时间`、`最近推送时间`、`推送次数`、`最近推送批次ID`、`推送消息ID`。

## 硬规则

- **联系人不落库**：姓名/邮箱/电话/WhatsApp/职位等明文**绝不写入任何 Base 表**，只在解锁卡片中展示。Base 只记录解锁状态（`是否解锁` + 4 个解锁系统字段）。
- **唯一去重键**：pool 布局为 `company_id + ":" + 线索ID`；按此键 upsert，同一键不建第二条。
- **来源**：pool 布局每行 `来源 = AI猎客`；`企业键 = cmp_sha256(规范化企业名)`。
- **群隔离**：`飞书群ID` 必须等于当前 `chat_id`；跨群记录整批拒绝。
- **字段缺失**：`线索ID` 为空拒绝写入；接口缺失字段留空，不写 `未提供`。
- **解锁落库**：仅在 `detail` 调用成功（调用即扣点）、解锁卡片确认发送（`contact_pushed`）后，写 `是否解锁=已解锁` + `解锁人/解锁时间/解锁方式（=AI猎客扣点）/解锁推送消息ID`。发送失败或 unknown 不改 `是否解锁`。
- **schema 调和**：写入前用 `base_schema_guard.py plan --schema pool` 做 add-only 调和；字段类型冲突/主字段非法则停止写入并报管理员。

## 复用脚本（dealclaw-buyer-leads-push）

- `scripts/lead_pool_guard.py ensure/map`：创建/复用/调和 pool，投影 guarded 记录为 upsert payload。
- `scripts/base_schema_guard.py plan --schema pool`：主表字段 add-only 调和。
- `scripts/lead_card_renderer.py render`：推送卡片（蓝色）。
- `scripts/contact_card_renderer.py render`：解锁卡片（绿色）。
