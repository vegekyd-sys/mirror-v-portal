# dealclaw-ai-hunter · 群消息卡片模板

> 展示样式对齐 `dealclaw-buyer-leads-push` 的 `references/message-template.md`：推送用蓝色宽屏卡片，解锁用绿色卡片；落库复用同一「企业线索池」Base。
> 所有卡片由脚本确定性渲染（复用 `dealclaw-buyer-leads-push` 的 `scripts/lead_card_renderer.py` / `contact_card_renderer.py`），模型不得手写组装卡片。

## 推送卡片（询盘买家）

### 选择与分组

- 选 `匹配动作 = push` 的记录，每批最多 5 条；`pool_only` / `exclude` 不进卡片。
- 按 `买家国家` 分组，每个国家一张卡（同一批次 ID）。
- 批次 ID = `chat_id + Asia/Shanghai 日历日 + 排序后线索ID`；发送前先落 `pending`。

### 卡片标题

```text
AI猎客｜来自{买家国家}买家的采购机会
```

蓝色 header、宽屏模式。

### 买家块

每个买家按确定性排序渲染：

```text
🥇 买家公司：{买家公司名称}    ⭐ 匹配分数：{AI匹配分}/100

需求意向：{需求意向}

关注产品：{关注产品}

买家特征：{买家特征}

报名参展：{报名参展展会}

💡 推荐理由：{由九维评分明细确定性生成}
```

- `买家公司名称`、`AI匹配分`（0–100）、九维 `评分明细`、`买家国家` 必填。
- `需求意向` / `关注产品` / `买家特征` / `报名参展展会` 仅在接口值非空时展示；不展示占位符、不编造。
- 推荐理由由九维评分明细确定性生成（核心=产品名/类目/国家，其次买家类型与其它非零加分项），不接受模型手写理由、不改分数或闸门。
- 买家可控 Markdown/提及/链接一律转义；多个买家块用分割线隔开。

### Footer 与动作

每张卡以分割线 + 原始 Base URL + 固定引导 + 一个主按钮结尾：

```text
📊 企业线索池：
{Base URL}

💬 请在企业线索池中标记每条线索的匹配结果（待确认/✅匹配/❌不匹配），系统将根据你的反馈优化后续推送。

🔓 需要买家联系方式？回复「解锁线索 线索ID」，系统扣除 360 点后把联系方式推送到本群。

[📊 打开企业线索池]
```

- Base URL 必须是 HTTPS、允许的飞书/Lark host、路径精确等于 `/base/<base_app_token>`；token 只出现在路径中才算有效。
- 用 `receive_id_type=chat_id`、精确 `receive_id`、`msg_type=interactive` 发送；card 对象精确序列化一次，不双重编码，失败不回退纯文本。

## 每日推荐收尾（定制询盘引导）

每日推荐的所有买家卡片推送完毕后，**最后补发一条收尾消息**（整批只发一次，不每条重复）：

```text
🎯 想进行专属定制询盘，可以联系 AI猎客专属运营，联系方式：
[运营二维码图片占位]
```

- 运营二维码必须来自配置项 `AI_HUNTER_OPS_QR_URL`，**禁止**编造或硬编码失效图片；未配置则省略该行。

## 解锁卡片（询盘买家联系方式）

### 触发

用户在群里回复 `解锁线索 <线索ID>`（或其它明确的解锁指令）→ 先向用户确认「解锁将扣 360 点」→ 用户明确确认后调 `POST {ADAPTER}/agent/buyerLeadsPlaza/detail`（`{"supplierId","trendId":"线索ID"}`），**调用即扣 360 点**（服务端记账，`supplier_id`+`trend_id` 幂等，同一组合不重复扣）→ 取联系人明文渲染解锁卡。用户未明确确认不得调 detail；同一 `线索ID` 已解锁（线索池 `是否解锁=已解锁`）不再调用，发重复解锁文案；detail 失败重试一次，仍失败发「已提交解锁，联系方式稍后重新拉取」，不编造联系人。

### 卡片标题

```text
AI猎客｜买家联系方式已解锁
```

绿色 header、宽屏模式，`enable_forward = false`。

### 卡片正文

```text
🔓 买家公司：{买家公司名称}
线索ID：{线索ID}

👤 联系人：{联系人姓名}
💼 职位：{职位}
📧 邮箱：{邮箱}
📱 电话：{电话}
💬 WhatsApp：{WhatsApp}

联系方式来自 AI猎客买家详情，仅发送至本群，不会写入企业线索池。请合规使用，勿二次分发。
```

- 每行仅在接口值非空时展示；校验徽标只来自 detail 响应的 `emailValid`/`mobileValid`/`whatsappValid` 整数 1（已验证）或 0（未验证），缺失不加徽标。
- 所有联系人为空时发无联系方式文案，不渲染卡。
- 联系人为展示-only，**绝不写进 Base、durable state 或日志**。

### 无联系方式文案

```text
线索 {线索ID} 已解锁，但买家暂未提供联系方式。
```

### 重复解锁文案

```text
线索 {线索ID} 的联系方式已于 {上次解锁日期} 推送到本群，请查看历史消息，无需重复解锁。
```
