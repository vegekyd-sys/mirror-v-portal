# Review — 画像确认 · 纠偏 · DealClaw

## When to Use

- 企业画像 / 买家画像生成后，引导用户确认或纠正
- 用户说「不对」「改成」「去掉」「加上」——任意环节
- 用户在买家搜索结果中标注 ✅/❌/⏸️

## 判断准则

**两层数据架构。** 企业级（全员共享）+ 用户级（按 `open_id` 隔离）。老板改企业画像 → 全员生效。销售标注偏好 → 只影响自己。偏好不跨企业，换企业从零开始。

**纠正双写。** 每次纠正或标注，同时改两份：
- 更新对应画像字段
- 追加 MEMORY.md 决策历史（时间 / 企业 / 字段 / 变更 / 原因）

MEMORY.md 四区：企业级数据 | 用户偏好 | 决策历史 | 跟进状态。首次纠正时文件不存在则自动创建。

**三维偏好晋升。** 国家 / 行业 / 产品 三个维度。✅ 标注 → 对应维度权重 +1。❌ 标注同一维度 **3 次** → 自动晋升为排除规则。晋升后不需要等用户说「记住」，直接生效。

**字段优先级。** 用户改过的字段以用户为准，不回退为 AI 推断值。AI 推断字段仅在用户未修改时保留。空字段 / pending 保持为空，不自行填充。

**纠正话术。** 「明白了，下次注意」——不说「已记录反馈」。不辩解，不解释为什么之前那样判断。

## 输出标准

画像确认时主动指出把握不准的字段请用户确认，不等用户来改。确认完成后给钩子 ≤10 字——「找买家？」「看市场洞察？」

## Actions

**指出不确定字段。** 画像生成后主动列出把握不准的字段。

**纠正双写。** 用户纠正 → 改画像 + 追加决策历史 + 同步更新知识库 persona，标记为 V 学习到的。

**偏好晋升。** 同维度纠正/标注满 3 次 → 自动晋升排除规则。

**锁定导向。** 确认完成 → 锁定 → 给下一步钩子。

## Boundaries

- 偏好不跨企业。换企业从零开始
- open_id 缺失时退化为共享模式
- 画像锁定后用户仍可修改
