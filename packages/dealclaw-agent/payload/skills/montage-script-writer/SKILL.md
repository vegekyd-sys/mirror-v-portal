# 混剪脚本/选片单 (Montage Script Writer)

> 夜班模式独立阶段：策划案通过 + 拍摄清单通过 + DAM素材可用 → 生成每条混剪视频的执行脚本。
>
> 策划案 §5 给出方向，本 skill 给出导航——具体到每个 DAM 素材 ID、每秒画面、每句钩子。

## 触发条件

当夜班模式或运营要求基于已通过的策划案和真实 DAM 素材生成混剪脚本。典型场景：
- 拍摄清单审核通过，DAM 素材已就绪
- 需要出混剪脚本/选片单给运营审核
- "给XX客户生成混剪脚本"

**Do NOT trigger on：**
- 策划案还没通过（先走策划案 skill）
- DAM 素材不可用（先走 material-verification）
- 单个视频分析（走 video-review-analysis）
- 企业宣传片脚本（走 corporate-video-script）

## 输入要求

必须确认以下输入齐全：
1. **最终审核通过的策划案**（§5 内容方向 + §7 拍摄清单）
2. **DAM 素材列表**（ID/名称/时长/originUrl，已验证可访问）
3. **目标市场/语言**

缺少任一输入 → 阻塞，等补材料。

## 核心规则

1. **脚本不是策划案里的选题**——选题是方向描述，脚本是帧级执行指令
2. **每条脚本必须引用真实 DAM 素材**——不能凭空描述画面，必须绑定到已验真的素材
3. **默认 3 条**——不同策划方向各 1 条（小明 2026-07-23 确认）
4. **每条 21-30 秒**——总时长不超过 30 秒

## 执行流程

### 1. 读取输入

- 策划案 §5：提取内容方向（3-5个），确认每个方向的选题和目标
- DAM 素材：确认素材 ID、名称、时长、可访问性
- 策划案 §7 拍摄清单：确认已拍摄内容

### 2. 选题分配

- 从策划案 §5 的 N 个方向中，选出 3 个最核心方向
- 每个方向对应 1 条脚本
- 选题分配原则：
  - 优先选有丰富 DAM 素材支撑的方向
  - 优先选差异化明显的方向（不要 3 条都像同一条视频）
  - 如果方向不足 3 个，按实际可支撑数量出

### 3. 素材匹配

对每个方向的脚本：
- 从 DAM 素材中匹配最合适的 4-6 条素材
- 匹配原则：画面与选题强相关、时长合适、画质可接受
- 每条素材记录：DAM ID、名称、时长（秒）、在脚本中的用途

### 4. 脚本撰写

每条脚本包含以下字段：

```markdown
### 脚本 #1：[一句话概括]

- **对应策划方向**：[方向名称]
- **目标市场/语言**：[如印尼语]
- **总时长**：[秒]

| 顺序 | DAM ID | 素材名称 | 时长 | 用途 |
|------|--------|---------|------|------|
| 1 | v539_slice_042 | 原料仓全景 | 3s | 开场Hook画面 |
| 2 | v539_slice_178 | 自动织机特写 | 4s | 工厂实力展示 |
| 3 | v539_slice_301 | QC检测台 | 3s | 品质证明 |
| 4 | v539_slice_089 | 成品仓库 | 3s | 产能展示 |
| 5 | v539_slice_412 | 打包出货 | 4s | 转化暗示 |

- **前3秒Hook（字幕/口播）**：[一个具体买家痛点问题或对比陈述]
- **正文字幕/口播要点**：[2-3句核心信息，匹配画面]
- **CTA**：[具体话术，引导评论/DM]
```

### 5. 生成飞书文档

输出一份飞书文档，包含：
- 标题：`{客户名} 混剪脚本/选片单 v{版本号}`
- 顶部：客户名、策划案版本、DAM 项目 ID、素材总数、脚本数量
- 主体：每条脚本的完整规格
- 末尾：备注（哪些方向因素材不足未纳入、哪些是高风险建议）

## Self-QC Gate（生成后自检）

**必须逐项自检，全部通过才能创建审核记录：**

| # | 检查项 | 标准 |
|---|---|---|
| 1 | 方向覆盖 | 每条脚本映射到一个不同的策划案方向 |
| 2 | 素材引用 | 所有 DAM ID 在素材列表中可找到，且名称/时长一致 |
| 3 | Hook 可用性 | 每条脚本 Hook 是具体话术，非泛泛"Welcome to our factory"；对应买家痛点 |
| 4 | CTA 存在 | 每条脚本末尾有 CTA（Comment/DM/Inquiry），非空 |
| 5 | 时长 | 每条 21-30 秒（素材累计时长在此范围内） |
| 6 | 数量 | 3 条（或按实际可用方向数量，不凑数） |
| 7 | 文档可读 | 运营/销售能看懂每条脚本的画面内容和目的 |

**QC 不通过处理：**
- 单条失败 → 修改该条，重新自检（最多 2 次）
- 多条失败 → 检查输入是否充足（素材不够？方向不合适？）
- 2 次重试仍不通过 → 写阻塞原因，不创建审核

**QC 通过后：**
- 创建飞书文档
- 在 Base 创建审核记录（审核状态=待审核）
- 执行单状态=待人工

## 失败模式

| 情境 | 处理 |
|---|---|
| 可用素材少于预期 | 减少脚本数量或说明哪些方向因素材不足未纳入 |
| DAM 素材无法访问 | 写阻塞原因，等待补链 |
| 策划案方向不足 3 个 | 按实际方向数量出脚本，不凑数 |
| 策划案方向描述模糊 | 基于方向目的推断具体画面需求，标注"需人工确认" |

## 边界

- ❌ 不创建 Demo 或调用视频生成
- ❌ 不修改已通过的策划案
- ❌ 不编造不存在的素材引用
- ❌ 不把策划案选题原文照搬为脚本——必须细化到帧级
- ✅ 素材不足/不可用时如实标注，不降级推断
