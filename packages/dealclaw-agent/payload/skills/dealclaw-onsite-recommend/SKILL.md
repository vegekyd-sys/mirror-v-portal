# 展会现场搜买家 / 推荐

## 触发

用户现场说：「搜现场买家」「现场推荐」「现场有哪些没邀约的买家」「再推荐一下现场买家」「现场还有哪些能聊的」等。

**不触发**：通用「找买家」走 `dealclaw-find-buyers`（画像评分 + 落线索池）；展前邀约走 `dealclaw-exhibition-invitation`。本 skill 只认「展会现场 + 即时搜未邀约买家」这一个场景，别跟 find-buyers 抢。

## 动作

调脚本（脚本内部会直接推气泡到群，并把本场推荐落进「本展会线索池」）：

```bash
python3 work/mio-api/dc_onsite_recommend.py run
```

脚本已负责：确定当前开展展会 → 拉现场买家（buyer onsite + 产品词）→ 剔除已邀约 + 剔除 excluded（黑名单/明确拒绝，排除不落）→ 主推/跟进分层 → 落本展会线索池（来源「展中推荐」）→ **每个定时最多推 10 家**（主推优先，超出顺延到下一次）。

**Agent 只做结果判断，不重复推卡**。读脚本 stdout 的 JSON：
- `status == "no_exhibition"`（或输出 NO_RUN）→ 告诉用户「当前没有正在开展的展会」。
- `results` 里 candidates 全 0 → 告诉用户「现场暂时没有未邀约的匹配买家」。
- 有 candidates → 气泡已由脚本分批推到群，Agent 简短回一句「已推 N 家，线索池见汇总气泡」即可，不重复发；落池失败时 `results[].pool.error` 有值，如实说明「明细已推、落池失败」。

## 交付口径（分批全明细）

- **每个定时最多推 10 家**（`ONSITE_MAX_PER_RUN`）：主推优先入选，超出部分**内部顺延到下一次定时**（不丢，只不在本轮推）。
  - **不向用户提“顺延”**（2026-09-17 客户口径）：用户不需要知道还有多少没推；他想看更多时直接问「还有没有推荐的买家」。
- **每条明细的内容**（2026-09-17 客户口径）：**公司名｜到场联系人（电话/WA）｜一句话简介**。
  - 联系人/电话是现场**直接拨号**的依据，必须展示；拿不到就写「到场联系人未提供」，**不编**。
  - 简介取公司简介字段（去 HTML、限长一点），方便一眼判断该不该邀约。
- **口吻是邀约到展位**（不是“给你一个名单”），摘要气泡带**本展会线索池入口**（入口不丢）。
- **禁止折叠**：不得再出现「其余 N 家未逐条列出」这类收敛文案——2026-09-15 现场实测 49 条被折叠成摘要、明细丢失，故改此口径（红线五.10）。
- 汇总气泡只是补充（含池入口），不替代明细。

## 线索池（每届展会一个池）

- 落池对象：本场推荐的**生存者**（已邀约不推、excluded 不落），公司名+官网幂等去重，重复跑不重建、不重复写同一条。
- 池布局：**每届展会一个独立 Base**，标题 `「<展会名>｜展中推荐线索池」`，**与企业主池分开**（`ensure_exhibition_lead_pool`，注册表键 `company_id::exhibition::exhibition_id`，不被 `canonical_company_id` 折叠）。
- 字段：来源 = **「展中推荐」**（与展后推荐的「展会线索」区分）、阶段 = **「现场对接中」**、公司名/官网/公司CDPID/国家/买家类型/推荐理由。

## 边界

- 未注册展会（orderRecords state=3 空）或当前无开展展会 → 脚本 NO_RUN，如实告知，不硬编。
- 推荐粗粒度（产品对路 + 买家类型/规模），宽进分层，不筛太狠；现场「聊上」比「精准」重要。
- 结果用分批气泡（公司名 + 国家 + 一句理由，按「交付口径」分批全发），不带 ✅❌ 按钮；线索**落本展会线索池**（来源「展中推荐」），池入口在汇总气泡（≤10 条时在末条明细气泡）。
- 定时推荐不归本 skill 管（cron 已注册当地时间 10/14/16 点），本 skill 只负责用户主动要求时的即时触发。

## 失败与验证

- 脚本报错 / 返回非 JSON → 如实告诉用户「查询失败」，贴关键报错，不编造推荐结果。
- 验证 gate：脚本 stdout 必须是含 `action == "onsite_recommend"` 的 JSON；以 `results[].candidates` 数量作为「有没有可推」的唯一依据，不以「脚本没报错」当成「有结果」；`results[].bubbles` 与 `results[].sent` 用于核验明细批是否全部发出（`sent < bubbles` 说明有批次没推出去）；`results[].pool` 给出落池数字（created/updated/skipped/excluded）与 `url`，`pool.error` 非空即落池失败（明细仍应正常推送）。
