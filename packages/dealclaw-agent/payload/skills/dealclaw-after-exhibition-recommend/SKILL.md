# 展后买家推荐

> 展会结束后，从本届到展买家清单里捞出「还没建联成功的理想买家」推荐给用户跟进。展会进行中走 onsite-recommend（展中现场）。

## 触发

| 用户说 | 动作 |
|------|------|
| 展后推荐 / 展后应该跟进谁 | 调 `recommend()` 出四组分流 |
| 查看本届到展买家 | 同上 |
| 本届还有哪些理想买家 / 哪些买家还没建联 | 同上 |

## 边界

- **只处理已结束或处于闭展日的展会**；展会进行中 → 路由 `dealclaw-onsite-recommend`。
- **必须指定或从上下文唯一确定 `target_exhibition_id`**；不确定先问，不猜。
- **候选范围只来自本届展会线索清单**（`candidate.exhibition_id == target`），线索池只用于去重、信息补全、历史关系判断，**不扩充候选**。
- **同一 customer 合并后保留所有互动证据**（去重是合并，不是删除）。
- **已建联买家进入 `connected_followups`，不得直接消失**（不进入「新买家推荐」，但进入独立跟进任务列表）。
- **扫码不算建联成功**——建联成功只认：isMeeting=1 / meeting interaction / 邮件 replied / WA 双向 / 人工确认。

## 动作

1. **推荐判断**：`work/mio-api/dc_after_exhibition_recommend.py` 的 `recommend()`（纯函数）——候选门禁 → 去重 → 线索池补历史 → 建联判定 → 画像匹配 → 排序理由 → 统计。
2. **写线索池**：`to_lead_pool_batch()`——除黑名单/明确拒绝外全部落线索池，来源「展会线索 + 本届展会名」。
3. **自动推送时机**：`work/mio-api/dc_after_exhibition_push.py` 的调度（见下），cron 每 15~30 分钟扫描，是否推由展会状态决定。

## 自动推送时机（按展会所在地时区）

| 时机 | 内容 |
|------|------|
| 闭展后 30~60 分钟（close_day） | 简版结果 |
| D+1 09:30（d1） | 正式跟进清单 |
| D+2、D+3 09:30（d2/d3） | 仅存在未处理高优先级买家时提醒，不重发整份名单 |
| 无新增价值或全部完成 | 静默 |

幂等键 `push_key = exhibition_id + push_type + recommendation_version`，同一 key 只成功发送一次。用户可随时主动触发（不受调度限制）。

## 失败处理

- 接口异常返回空 → 延迟重试，不发送「0 家买家」。
- 数据未同步 → 显示「现场数据仍在汇总」，不生成最终结论。
- 连续重试失败 → 只提示数据同步异常，不伪造推荐。
- 自动推送失败不影响用户主动触发查询。
