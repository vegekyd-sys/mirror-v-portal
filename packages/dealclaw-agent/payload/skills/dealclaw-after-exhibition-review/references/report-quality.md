# 正式展后报告质量标准

## 报告层级

正式版同时服务企业老板、外贸负责人和执行销售。正文先给经营判断，再给诊断证据和行动；完整名单、原始沟通和算法明细放在附录或通过链接下钻。

推荐结构：

1. 封面与报告身份：企业、展会、日期、模式、数据截止时间、报告版本。
2. 一页管理层摘要：目标达成、主要收获、核心阻塞、未来 72 小时最重要动作。
3. 参展目标与数据可信度：原定目标、实际覆盖、缺失来源、当前能与不能得出的结论。
4. 全链路漏斗：每层唯一客户数、转化率、与目标/历史/可靠基准的差异。
5. 根因诊断：最多三个关键阻塞，每个使用“事实-解释-限制-行动-验证指标”。
6. 买家机会组合：按匹配度、阶段、优先级和下一步展示分布，不把名单表当分析。
7. 重点客户深析：默认 5 至 10 家，每家有独立证据、需求、异议、关系状态和下一步。
8. 买家需求与市场反馈：涉及客户数、提及次数、样本量、代表性证据和产品含义。
9. 小元使用复盘：可用、被提供、实际使用、成功、产生贡献五层，并区分产品与用户原因。
10. 72 小时、7 天、30 天行动：对象、负责人、截止时间、成功标准。
11. 方法与附录：口径、数据源、水位、去重方法、基准定义、完整清单链接。

`close_out` 尚不能证明成交效果，重点写现场收口和行动；`conversion_review` 才评价回复、报价、样品和商机推进。

## 分析深度

每个关键诊断必须包含：

```text
观察事实：发生了什么，分有效样本和覆盖率是多少。
业务解释：这对参展结果意味着什么。
证据限制：还缺什么，哪些因果不能确认。
建议动作：对谁、做什么、何时完成。
验证指标：怎样判断建议有效。
```

只重复漏斗数字不算诊断。“可能跟进不及时或需求不明确”如果没有时间间隔、互动内容或需求字段支持，只能列为待验证假设。

## 重点客户标准

重点客户表用于扫描，后面必须有逐客户简析。每家公司至少包含：

- 为什么符合本企业理想买家，而不是通用“产品高度匹配”。
- 本届发生了什么互动，证据来自哪条记录。
- 已确认需求、数量、用途、预算、交期、规格或异议；未确认项明确标识。
- 当前关系和商机阶段。
- 下一步动作、负责人、截止时间和完成标准。
- 客户档案或沟通明细链接。

不同客户出现相同理由和相同动作时，必须确认它们确有相同证据；批量复制文案不得用于正式报告。

## 图表与版式

- 正式 PDF 使用 A4，保持一致的页眉、页脚、页码、字体和间距。
- 首页不堆四个含义重复的 KPI，例如“目标买家”和“漏斗起点”不能重复展示同一数字。
- 漏斗图显示分母、分子和数据覆盖，不把“到展/会面”等不同事件合并成一层。
- 表格不应跨整页堆满所有买家；正文展示重点和分布，完整名单放附录或外链。
- 避免大面积空白、孤立标题、跨页断裂和过长单元格。
- 每张图表必须有结论性标题和口径注释，而不只是装饰。

## 数据不足时的降级

缺少 meeting、scan、attendance、email 或 WhatsApp 数据时：

1. 标记为“初步复盘”或“数据待补版”。
2. 展示来源状态和预计影响。
3. 只输出当前可证实的事实。
4. 将根因写成待验证假设。
5. 给出补数据和下一步行动。

禁止用 mock、示例或历史报告中的公司和数字生成客户正式报告。测试数据必须在封面、页眉和文件名中明显标识“DEMO / 非真实数据”。

## 交付前检查

- 数字能回到 `report-data.json`，且相同指标在全文一致。
- 所有重点客户具有差异化理由和证据引用。
- 需求洞察区分唯一客户数与提及次数。
- 所有基准披露样本、时间和口径。
- 所有行动有负责人、截止时间和成功指标。
- 不含未经证实的成交、复购、ROI、效率或因果承诺。
- 数据不足时没有伪装成完整正式报告。
- PDF 逐页视觉检查无异常后才交付。
