# DealClaw 展后诊断复盘

## 定位

把展后报告从数据看板升级为参展效果诊断与行动计划。报告首先帮助参展企业回答：本届获得了什么、问题发生在哪一环、哪些买家和动作最值得优先推进、下次应改变什么。

报告不是 CSM 的归责材料。产品使用数据只能帮助发现流程机会，不能把效果不佳默认归因于客户“不会用工具”，也不能承诺下届效果、订单或复购必然提升。

## 与其他能力的边界

- 展中找现场买家：交给 onsite recommendation 能力。
- 展后寻找尚未建联买家：读取 after-exhibition recommendation 的分流结果，本 Skill 不重复搜索全量线索池。
- 邮件或 WhatsApp 发送：只生成建议和待办，不自动发送。
- 日常营销复盘：交给 adaptive planner；本 Skill 只分析指定届展会及其后续转化窗口。

## 复盘模式

根据数据成熟度选择模式，不要用闭展当天的数据假装已经看到了长期转化：

1. `close_out`：闭展后至 D+1。聚焦现场成果、数据完整度、优先买家和 72 小时行动。
2. `conversion_review`：默认 D+7，可按业务周期延长。加入送达、回复、会议、样品、报价和商机推进结果。
3. `refresh`：用户主动要求更新时，在同一展会报告上刷新事实、诊断和行动状态，保留旧版本的关键结论。

## 必要输入

至少需要明确的 `exhibition_id`、企业身份和本届展会时间范围。所有候选、统计和诊断先限定到本届展会；企业线索池只用于主体去重、历史关系和信息补全，不得扩充本届样本。

按可用性读取：

- 展会元数据：名称、国家、时区、起止时间、目标产品和目标买家。
- 本届漏斗事件：曝光、邀约、确认、到展、到展位、扫码、会议和有效商洽。
- 客户与商机：匹配度、stage、followup_priority、priority_reason、next_step、contact_policy、opportunity_status。
- 沟通明细：邮件、WhatsApp、会议、扫码；慧记 transcript 和慧译 translation 是 meeting 的 artifacts，不重复计为互动。
- 展后结果：送达、回复、退信、二次会议、样品、报价和成交状态。
- 产品使用事件：功能可用性、使用次数、成功/失败、数据覆盖和可验证的时间节省。
- 基准数据：本企业历史展会或口径一致的匿名同行分位数。

生成报告前必须阅读 [references/report-contract.md](references/report-contract.md)。它定义完整字段、漏斗口径和结构化输出；不能只凭本文件中的章节标题自由发挥。

## 工作流

### 1. 锁定口径与数据完整度

先按企业、`exhibition_id` 和唯一客户去重。区分“到达展会”与“到达本企业展位”，区分“扫码”与“有效商洽”，区分“发出消息”与“买家回复”。

为每个数据源标记 `ready | partial | unavailable | error`。关键来源缺失时仍可生成部分报告，但必须明确缺口及其影响；接口异常或未同步不能写成 0。

### 2. 生成结果摘要

先给一句结论，再给不超过三个最重要的发现。结论必须同时包含成果、主要阻塞和最优先动作，避免“优质资产”“潜力巨大”等没有判定依据的宣传语。

### 3. 构建展会与转化漏斗

漏斗每一层使用唯一公司数，并显示分母、转化率和数据覆盖。只比较口径一致、包含关系合理的相邻阶段；不能把全量历史买家、匹配买家和本届到展买家串成伪漏斗。

推荐主漏斗（轻量化 5 层，其余作为明细信号，不单列）：

```text
目标买家 → 已邀约 → 到展/会面 → 有效商洽 → 商务推进
```

明细信号挂靠在对应层下：已邀约含「确认参与」；到展/会面区分「本届到展」与「到达展位/实际会面」；有效商洽含「需求明确」；商务推进含「已执行跟进、买家回复、报价/样品/二次会议」。展示时只在有可靠数据时展开明细，不硬凑。

没有某一层的可靠数据时跳过该层并标注，不用 0 补齐。

### 4. 诊断最主要的阻塞点

从最靠前且证据充分的异常环节开始判断。每个诊断包含：观察事实、可支持的解释、仍不能确定的因素、建议动作和验证方式。

不得把相关性写成因果。执行诊断前必须阅读 [references/diagnostic-rules.md](references/diagnostic-rules.md)。

### 5. 形成买家资产与跟进计划

分别呈现：

- 已触达但未实质建联的高优先级买家。
- 已建联且等待报价、样品、资料或二次会议的买家。
- 长期培育买家。
- 明确拒绝、身份不匹配、失效或停止触达的记录。

匹配度表示理想买家契合度，商机阶段表示关系进展，跟进优先级表示现在先做什么；三者不得混用。每个优先对象必须给出证据化理由、下一步、负责人和截止时间。

**重点客户深析（Agent 推理生成，不写进脚本）**：从优先跟进买家中选 5-10 家做逐家深析，由 Agent 读每家的原始 interaction 推理生成，禁止模板化复制。每家至少写清五项：①为什么是理想买家（基于本届互动证据，不能用「产品高度匹配」这种空话）；②本届互动证据（哪条 interaction、什么时间、发生了什么，引用 subject/信号）；③已确认的需求（产品/数量/用途/预算/交期/规格/异议，未确认的标「待确认」）；④当前关系与商机阶段；⑤下一步（动作 + 负责人 + 截止时间 + 完成标准）。深析必须来自 interaction 证据，证据不足的只能进「待核验清单」，不能写深析。

### 6. 分析需求与现场反馈

从有原始证据引用的 interaction signals 聚合产品需求、数量、用途、预算、交期、规格、异议和渠道偏好。注明样本量；同一客户重复提及只按一个客户计数，除非明确展示“提及次数”。

### 7. 评估产品使用健康度

仅在同时掌握“功能当时可用、用户有使用机会、实际使用记录”时判断使用缺口。区分产品故障、数据未接入、用户未使用和场景不适用。

不能根据“使用次数少”直接断言客户浪费时间，也不能把未使用功能算作参展效果差的原因。产品建议写成下一届可验证的实验，例如培训、现场流程或功能配置，并说明成功指标。

### 8. 输出行动与复盘计划

`close_out` 默认给出 72 小时、7 天和下一届准备动作；`conversion_review` 给出继续推进、长期培育、停止投入和下一轮实验。行动总数保持可执行，优先展示已经到期或承诺过的事项。

## 基准比较

优先级依次为：本企业同产品/同市场历史展会、口径一致的匿名同行中位数与上四分位、无基准只展示自身漏斗。

使用基准时必须显示样本、时间范围、地区/行业、指标定义和数据覆盖。样本不足、口径不一致或来源不明时不得展示“行业均值”或“优秀同行”。禁止披露其他企业身份和可反推的敏感数据。

## 输出

默认生成：

1. `report-data.json`：事实、口径、诊断、证据、行动和完整度，作为可重算数据层（事实唯一来源）。
2. `report.html`：自包含的 HTML 阅读层（不是飞书文档），浏览器直接打开，内嵌样式、无外部依赖。
3. `report.pdf`：由 `report.html` 经 `google-chrome --headless --print-to-pdf`（或 `wkhtmltopdf`）转出，供用户下载。

文档建议分节（HTML 按此顺序渲染，一个 section 对应一块）：

```text
展后复盘结论
本届收获
漏斗与关键阻塞
优先买家与下一步
买家需求和现场反馈
小元如何继续帮你
72小时 / 7天行动
数据口径与完整度
```

HTML 布局要求：结论和 KPI 数字块放首屏，漏斗用可视化条形图或阶梯图，买家行动项用表格；报告内不放完整邮件、会议原文或个人联系方式，详细名单通过线索池/客户档案链接下钻。PDF 转换后需校验分页不截断表格。

管理层默认先看到结论、机会和行动，详细名单通过线索池、沟通明细和客户档案链接下钻。不要把完整邮件、会议原文或个人联系方式铺在报告正文。

### 专业报告最低标准

生成 PDF、正式飞书文档或供 CSM 交付的报告时，必须阅读并满足 [references/report-quality.md](references/report-quality.md)。正式报告不是聊天摘要的排版版，至少应具有：目标与口径、数据完整度、漏斗诊断、机会组合、重点客户深析、需求洞察、产品使用复盘、分阶段行动和方法附录。

篇幅由有效信息决定，不为凑页数重复内容；但完整数据下的正式版通常需要 6 至 10 个 A4 页面或等量飞书文档信息。若数据不足以支持完整报告，标题必须标为“初步复盘”或“数据待补版”，并列出缺口，不能用三页通用摘要冒充正式诊断报告。

重点客户不能共用一段模板化推荐理由。每个被列为优先跟进的客户至少要展示两项该客户特有的证据，以及明确的动作、负责人、截止时间和成功标准。没有差异化证据时只能进入待核验清单。

在正式渲染前运行：

```bash
python3 scripts/validate_report.py --input /path/to/report-data.json
```

校验不通过时不得标记为正式报告或发送给用户。修复结构化数据与诊断，不要只修改 PDF 文案绕过校验。

## 硬边界

- 不编造行业均值、优秀案例、采购意向、订单概率、节省时间或投资回报。
- 不把 VIP、历届到展、扫码或存在决策人单独等同于高采购意向。
- 不把“本届报名”“本届到展”“到达展位”“有效商洽”混为一谈。
- 不将历史线索池买家计入本届成果；同一客户跨来源只计一次。
- 不把 A/B/C 匹配度写成成交概率；优先级必须有当前证据。
- 不生成“效果肯定翻倍”“一定拿到订单”等承诺。
- 不自动发送消息、修改客户状态、压制线索或开启定时任务。
- 用户可对结论和建议进行修正；修正回写结构化数据并保留来源，不只修改渲染文档。
