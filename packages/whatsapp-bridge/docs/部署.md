# WhatsApp 桥接服务部署文档

本文说明如何把 `whatsapp-platform-bridge` 部署到可对外提供服务的环境。服务职责：把 YCloud WhatsApp 与飞书客服群话题双向同步，并提供 Partner Direct Link 嵌入式注册（开通 WABA）。

相关文件：

- 环境变量模板：[`.env.example`](../.env.example)
- 手工建表 SQL（Prisma 不可用时的兜底）：[`ops-init-postgres.sql`](./ops-init-postgres.sql)

---

## 1. 架构

```text
买家 WhatsApp
    │  YCloud
    ▼
YCloud Webhook  ──POST /webhooks/ycloud──►  桥接服务 (Node / Fastify)
                                                    │
                                                    ├─ PostgreSQL（会话 / 消息 / WABA 绑定）
                                                    ├─ 调 YCloud API 发 WhatsApp
                                                    └─ 调飞书 API 建群、拉话题、同步消息
飞书客服话题回复 ──POST /webhooks/feishu──►  桥接服务 ──► WhatsApp

智能体 / 业务系统 ──HTTP /api/whatsapp/*──►  桥接服务
```

要点：

- **不要直连** `api.ycloud.com` 或 Meta API。业务侧只调本服务 HTTP。
- 服务监听 `0.0.0.0:$PORT`（默认 `3000`），Webhook 必须是公网 HTTPS。
- 当前生产启动走 `tsx src/index.ts`，**不是**编译后的 `dist/`。机器上要有 Node、依赖和 `tsx`。

## 2. 环境要求

| 项 | 要求 |
|---|---|
| Node.js | `>= 20`（见 `package.json` `engines`） |
| 包管理 | npm（仓库自带 lockfile 则用 `npm ci`） |
| 数据库 | PostgreSQL 14+（阿里云 RDS 可用） |
| 出网 | 能访问 `https://api.ycloud.com`、`https://open.feishu.cn`（国际飞书改 `FEISHU_BASE_URL`） |
| 入网 | 公网 HTTPS 打到本服务的 `/webhooks/ycloud`、`/webhooks/feishu` |
| 时钟 | NTP 校准。YCloud 验签允许偏差约 **5 分钟**，时钟不准会 401 |
| 磁盘写权限 | WABA 绑定成功后会尝试写入 `.env.production` 等文件；写失败不影响运行，绑定仍会进库 |

无 Docker / compose。生产可用 systemd、pm2，或任意能常驻 Node 进程的方式。

## 3. 配置文件怎么加载

启动时 `src/loadEnv.ts` 按 **APP_ENV** 读文件，**后者覆盖前者**：

1. `.env.shared` — 多环境共用密钥（例如 `YCLOUD_API_KEY`）
2. `.env.<APP_ENV>` — `.env.development` / `.env.test` / `.env.production`
3. `.env.<APP_ENV>.local`
4. `.env.local`
5. `.env`

`APP_ENV` 判定：

| 启动命令 | APP_ENV |
|---|---|
| `npm run dev` | `development` |
| `npm run start:test` | `test` |
| `npm run start` / `npm run start:prod` | `production` |
| 显式 `APP_ENV=production` / `NODE_ENV=production` | `production` |

以上 env 文件均在 `.gitignore` 中，**不要提交真实密钥**。

查看实际加载了哪些文件：

```bash
DEBUG_ENV=1 npm run start
```

### 3.1 推荐拆分

| 文件 | 放什么 |
|---|---|
| `.env.shared` | `YCLOUD_API_KEY`、飞书 `APP_ID`/`SECRET` 等密钥（若测试/生产共用同一套） |
| `.env.development` | 本地端口、测试库、`YCLOUD_SKIP_SIGNATURE=1`（仅本地） |
| `.env.production` | 生产库、`PORT`、公网 `WHATSAPP_BRIDGE_BASE_URL`、`MIO_CDP_SUPPLIER_ID`；**不要**跳过验签 |

测试和生产必须用**不同**的 `DATABASE_SCHEMA` 或不同数据库，避免会话和 WABA 绑定串环境。

### 3.2 环境变量说明

#### 进程与路由

| 变量 | 必填 | 说明 |
|---|---|---|
| `APP_ENV` | 建议显式设置 | `development` / `test` / `production` |
| `PORT` | 否 | 默认 `3000` |
| `WHATSAPP_BRIDGE_BASE_URL` | 智能体侧建议 | 桥接对外基址，去掉末尾 `/`。服务监听不依赖它 |
| `DEBUG_ENV` | 否 | `1` 时打印加载了哪些 env 文件 |
| `MIO_CDP_SUPPLIER_ID` | 开通 WABA 时必填 | CDP 供应商 ID，作为 Partner Direct Link 的 `partnerCustomerId`。未配则创建 Onboarding Link 返回 400 |

#### 数据库

| 变量 | 必填 | 说明 |
|---|---|---|
| `DATABASE_URL` | 是 | `postgresql://host:5432/dbname`。可带或不带账号 |
| `DATABASE_USER` | URL 无账号时 | 拼进 URL |
| `DATABASE_PASSWORD` | 同上 | 仅当 URL 还没有 username 时才会写入 |
| `DATABASE_SCHEMA` | 强烈建议 | 默认 `public`。本仓库 migration / 建表 SQL 使用 **`whatsapp_platform_bridge`** |

加载后会把 `?schema=` 写进 `DATABASE_URL`，Prisma 只操作该 schema，不碰同库其它表。

#### YCloud

| 变量 | 必填 | 说明 |
|---|---|---|
| `YCLOUD_API_KEY` | 是 | 调 YCloud 发消息 / 列号 / 列模板 / 建 Onboarding Link |
| `YCLOUD_WEBHOOK_SECRET` | 生产必填 | 校验请求头 `ycloud-signature` |
| `YCLOUD_SKIP_SIGNATURE` | 仅本地 | `1`/`true`/`yes` 跳过验签。**生产必须为 0 或不设** |
| `YCLOUD_WABA_ID` | 发消息前需要 | 可空：走嵌入式注册，Webhook `PARTNER_ADDED` 后后端写入 env + `AppSetting` |
| `YCLOUD_FROM` | 建议 | 当前 WABA 默认企业号，E.164（如 `+85251111111`）。绑定成功后也可自动填 |

YCloud API 基址写死为 `https://api.ycloud.com/v2`，无需配置。

#### 飞书

| 变量 | 必填 | 说明 |
|---|---|---|
| `FEISHU_APP_ID` / `FEISHU_APP_SECRET` | 是 | 企业自建应用 |
| `FEISHU_VERIFICATION_TOKEN` | 建议 | URL 校验时核对 |
| `FEISHU_ENCRYPT_KEY` | 生产必填 | 验签与解密加密事件。未跳过验签时缺它会 500 |
| `FEISHU_SKIP_SIGNATURE` | 仅本地 | 生产不要开 |
| `FEISHU_BASE_URL` | 否 | 默认 `https://open.feishu.cn` |
| `FEISHU_CHAT_ID` | 否 | 客服群。空则查已有「WhatsApp 客服」群，没有就自动建 |
| `FEISHU_NOTIFY_CHAT_IDS` | 否 | 买家来信额外提醒的群 `oc_...`，逗号分隔 |
| `FEISHU_NOTIFY_CHAT_NAMES` | 否 | 按群名解析提醒群（机器人必须已在群里） |
| `FEISHU_INVITE_OPEN_IDS` | 否 | 建客服群时拉入的用户 |
| `FEISHU_INVITE_EMAILS` / `FEISHU_INVITE_MOBILES` | 否 | 用通讯录换成 open_id 再拉人 |
| `FEISHU_INVITE_APP_IDS` | 否 | 拉入客服群的其它机器人 App ID（`cli_` 开头）。只有这些机器人在话题里的回复才会转到 WhatsApp |

CSV 类变量支持英文逗号、中文逗号或空白分隔。

## 4. 数据库

### 4.1 权限

应用账号至少需要对 schema `whatsapp_platform_bridge`：

- `USAGE`（以及建表时的 `CREATE`，若用 Prisma migrate）
- 表的 `SELECT, INSERT, UPDATE, DELETE`

阿里云 RDS 常见限制：**不能创建 shadow database**。因此：

- **不要**在 RDS 上跑 `npx prisma migrate dev`
- **不要**直接跑未加载 env 的 `npx prisma ...`（读不到 `.env.shared` / `.env.production`）
- 用仓库脚本：`npm run prisma:migrate:deploy`

### 4.2 推荐：Prisma migrate deploy

在项目根目录、env 已配好之后：

```bash
npm ci
npm run prisma:generate
npm run prisma:migrate:deploy
```

`postinstall` 也会 `prisma generate`。`scripts/run-with-env.ts` 会按第 3 节规则加载 env，再执行 Prisma。

当前 migration：

1. `20260825090500_init_postgres`
2. `20260903070000_waba_onboarding`
3. `20260904060000_feishu_apps`
4. `20260904080000_feishu_app_invite_bots`

本地第一次开发可用 `npm run prisma:migrate`（`migrate dev`）。它需要 shadow DB，RDS 通常不行。

若 schema 尚不存在且账号有建 schema 权限：

```bash
npx tsx scripts/ensure-pg-schema.ts
```

init migration 里也有 `CREATE SCHEMA IF NOT EXISTS "whatsapp_platform_bridge"`。

### 4.3 兜底：手工执行 SQL

无法跑 Prisma CLI 时，在目标库执行 [`ops-init-postgres.sql`](./ops-init-postgres.sql)（已含 `WabaOnboarding`）。

注意：

- 先确认该 schema 下还没有这些表，文件**不是**完全幂等。
- 手工建表后若再跑 `prisma migrate deploy`，可能因缺 `_prisma_migrations` 记录而冲突。选定一种方式后不要混用。
- 把 SQL 末尾 `GRANT` 里的 `<app_user>` 换成真实账号。

## 5. 飞书应用

使用**企业自建应用**（internal）。

### 5.1 权限（按实际调用）

在开放平台开通并以**应用身份**发布。至少覆盖：

| 能力 | 用途 |
|---|---|
| 获取 `tenant_access_token` | 所有服务端调用 |
| 创建/获取/列出群、拉人、拉机器人、进群 `me_join`、群分享链接 | 自动建「WhatsApp 客服」群、把机器人拉进发起群 |
| 发消息、回复话题、转发话题、表情回复、读消息、下载消息资源 | 文本/图片同步 |
| 上传图片 `im:resource` | WhatsApp 图片转到飞书 |
| 通讯录：可用范围、按邮箱/手机换 open_id、`contact:user.employee_id:readonly` | `FEISHU_INVITE_EMAILS` / `MOBILES` |

应用身份拿不到用户 `open_id` 时，按飞书提示开通「获取用户 user ID」并以应用身份发布。

### 5.2 事件订阅

- 请求网址：`https://<公网域名>/webhooks/feishu`
- 订阅：`im.message.receive_v1`
- 加密/验签：填写 `Encrypt Key`、`Verification Token`，与 env 一致
- 保存时飞书会发 `url_verification`，服务原样返回 `challenge`

机器人需要能进群、发话题。客服群类型为**私有群** `chat_type=private`，名字固定 **「WhatsApp 客服」**。`FEISHU_CHAT_ID` 可空。

话题回复同步规则：人工回复会转到 WhatsApp；桥接自己的机器人消息忽略；其它机器人只有在 `FEISHU_INVITE_APP_IDS` 里才会同步。带 `@` 的消息只留在飞书。

## 6. YCloud / WhatsApp

### 6.1 Webhook

在 YCloud 控制台配置：

- URL：`https://<公网域名>/webhooks/ycloud`
- Secret：写入 `YCLOUD_WEBHOOK_SECRET`
- 至少订阅：
  - `whatsapp.inbound_message.received` — 买家来信
  - `whatsapp.message.updated` — 投递状态（失败会写回飞书话题）
  - `whatsapp.business_account.updated` — 嵌入式注册绑定 WABA（`PARTNER_ADDED`）

验签请求头：`ycloud-signature`（`t=` 时间戳 + `s=` HMAC）。生产关闭 `YCLOUD_SKIP_SIGNATURE`。

### 6.2 API Key 与 WABA

- `YCLOUD_API_KEY` 放 `.env.shared` 或对应环境文件，**不要打印、不要提交 git**。
- 未绑 WABA 时：调用方未传 `wabaId`（应从 env `YCLOUD_WABA_ID` 读取），发消息 409 `WHATSAPP_WABA_REQUIRED`，列号/列模板 400。先 `POST /api/whatsapp/onboarding-links`。
- 客户完成 Meta 流程后，Webhook 落库 `WabaOnboarding`，并把 `YCLOUD_WABA_ID` / `YCLOUD_FROM` 写入 **env 文件和当前进程**（给智能体下次读取）。智能体 HTTP 接口**必须**带请求里的 `wabaId`，不会用后端进程环境变量或库里旧 `CONNECTED` 顶上。
- 发消息的 `from` 必须是该 `wabaId` 下的企业号，否则 409 `WHATSAPP_FROM_NOT_IN_WABA`。
- 列号、列模板：`GET .../phones?wabaId=`、`GET .../templates?wabaId=`。

中国大陆 `+86` 可能被 YCloud 拒绝（`MESSAGING_REGION_UNSUPPORTED`），属通道侧限制，不是部署配错。

### 给运维的第一次发布交付（你这边准备这些）

代码和文档：

| 交付物 | 说明 |

- **PostgreSQL 14+**（RDS 可用），库账号要有在指定 schema 建表权限

- 出网放行 `https://api.ycloud.com`、`https://open.feishu.cn`
- NTP；进程用 systemd 或 pm2 常驻
- 部署目录建议 `/opt/whatsapp-platform-bridge`，运行用户对目录可读；若要绑定 WABA 后回写 env，还需能写 `.env.production`

由业务/开发填好、通过安全渠道交给运维写入 `.env.production` 的值（**不要进 git、不要发群**）：

| 变量 | 谁提供 |
|---|---|
| `DATABASE_URL` / `DATABASE_USER` / `DATABASE_PASSWORD` | 运维（RDS） |
| `DATABASE_SCHEMA=whatsapp_platform_bridge` | 固定用这个名字 |
| `YCLOUD_API_KEY` | 业务（YCloud 控制台） |
| `YCLOUD_WEBHOOK_SECRET` | 业务（与 YCloud Webhook Secret 同一份） |
| `WHATSAPP_BRIDGE_BASE_URL` | 运维（上线后的 `https://公网域名`，无末尾 `/`） |
| `MIO_CDP_SUPPLIER_ID` | 业务（CDP 供应商 ID，开通 WABA 用） |
| `YCLOUD_WABA_ID` / `YCLOUD_FROM` | 可空，开通成功后服务会自己写回 |

飞书 `FEISHU_APP_ID` / `SECRET` / `TOKEN` / `ENCRYPT_KEY` **可以不交给运维写进桥接 env**，由智能体初始化 `POST /api/feishu/apps` 登记。

部署完成后你还要自己做（运维给完域名即可）：

- YCloud Webhook：`https://域名/webhooks/ycloud`，订阅入站、投递状态、`whatsapp.business_account.updated`
- 飞书事件地址：智能体注册返回的 `https://域名/webhooks/feishu/<appId>`
- `GET https://域名/health` 为 `"ok": true`

生产启动命令是 `npm run start`（`tsx src/index.ts`），**不要** `npm run build`，**不要** `npm ci --omit=dev`。

### 8.1 第一次部署

1. 机器：Node.js `>= 20`，能出网访问 YCloud / 飞书，公网 HTTPS 反代到本服务 `PORT`（默认 3000）。PostgreSQL 已建库。
2. 放代码：

```bash
git clone <仓库> /opt/whatsapp-platform-bridge
cd /opt/whatsapp-platform-bridge
git checkout <发布 tag 或 commit>
node -v
npm ci
```

3. 写配置（只做这一次，以后更新不要覆盖）：

```bash
cp .env.example .env.production
# 需要共用密钥时再准备 .env.shared
chmod 600 .env.production .env.shared 2>/dev/null || true
```

生产至少填：`DATABASE_URL`（及 `DATABASE_USER` / `DATABASE_PASSWORD`）、`DATABASE_SCHEMA=whatsapp_platform_bridge`、`YCLOUD_API_KEY`、`YCLOUD_WEBHOOK_SECRET`、`WHATSAPP_BRIDGE_BASE_URL=https://你的域名`、`MIO_CDP_SUPPLIER_ID`（要开通 WABA 时）。**不要**设 `YCLOUD_SKIP_SIGNATURE=1` / `FEISHU_SKIP_SIGNATURE=1`。飞书 `FEISHU_APP_ID` 等可由智能体初始化 `POST /api/feishu/apps` 登记，桥接启动可以不写。

运行用户要对项目目录有读权限；若希望绑定 WABA 后回写 env，还需要对 `.env.production` 有写权限。

4. 建 schema（库账号有权限时）并迁移：

```bash
export APP_ENV=production
npx tsx scripts/ensure-pg-schema.ts
npm run prisma:migrate:deploy
```

RDS 只用 `migrate:deploy`，不要 `migrate dev`。

5. 常驻启动（见第 10 节 systemd / pm2），或前台试跑：

```bash
npm run start
```

6. 探活：`curl -sS https://你的域名/health`，应有 `"ok": true`。
7. 把 YCloud Webhook 配成 `https://你的域名/webhooks/ycloud`。飞书事件地址用智能体注册返回的 `https://你的域名/webhooks/feishu/<appId>`（不要再用无 appId 的旧路径，除非桥接 env 里仍写着 `FEISHU_*`）。
8. 用 systemd/pm2 做成开机自启后再撤掉前台进程。

### 8.2 以后更新（全量换源码，保留 env）

每次发版都是替换代码，**不是**只传一个 build 包。务必保留 `.env.production` / `.env.shared`，不要用空模板盖掉线上密钥。

```bash
cd /opt/whatsapp-platform-bridge

# 1. 停进程
sudo systemctl stop whatsapp-platform-bridge
# 或：npx pm2 stop wa-bridge

# 2. 更新代码（二选一）
git fetch && git checkout <新 tag 或 commit> && git pull
# 若是拷贝/解压：覆盖 src、prisma、package.json 等，不要覆盖 .env*

# 3. 依赖（package-lock 有变才必须；保险起见每次都跑）
npm ci

# 4. 只应用尚未执行的 migration（没有新 migration 也会很快结束）
export APP_ENV=production
npm run prisma:migrate:deploy

# 5. 启动
sudo systemctl start whatsapp-platform-bridge
# 或：npx pm2 start wa-bridge

# 6. 探活
curl -sS https://你的域名/health
```

说明：

- **不用** `npm run build`。`start` 读的是 `src/`。
- `npm ci` 会按 lockfile 重装 `node_modules`，属于正常的全量依赖安装。
- 有新 Prisma migration 才必须 `migrate:deploy`；没跑的话新表/新列不存在，启动或请求会报错。
- 飞书 / YCloud 控制台 URL 没变就不用改；ngrok 域名变了才要改事件地址。
- 回滚：停进程 → `git checkout <上一版本>` → `npm ci` → **不要** down-migrate 生产库 → 启动。若新版本加过表/列，旧代码一般仍能在新结构上跑。

### 8.3 健康检查

```bash
curl -sS https://你的域名/health
```

期望类似：

```json
{
  "ok": true,
  "partnerCustomerId": "...",
  "wabaId": "...",
  "wabaBound": true,
  "wabaCount": 1,
  "from": "+852..."
}
```

`wabaBound=false` 表示还没绑 WABA，发消息前要先嵌入式注册，不是部署失败。

## 9. 公网与反向代理

YCloud、飞书都要访问公网 HTTPS。典型：Nginx / Caddy / SLB → `127.0.0.1:3000`。

要求：

1. **不要改写请求体**。验签用原始 body。
2. 反代超时不要太短（Webhook 会先 200，再异步处理，一般很快）。
3. 只把 443 暴露公网，3000 仅本机或内网。
4. 证书有效（Let's Encrypt 等）。

Nginx 示例：

```nginx
server {
    listen 443 ssl http2;
    server_name bridge.example.com;

    # ssl_certificate     ...;
    # ssl_certificate_key ...;

    client_max_body_size 12m;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_request_buffering on;
    }
}
```

把下列 URL 配到控制台：

| 通道 | 路径 |
|---|---|
| YCloud | `https://bridge.example.com/webhooks/ycloud` |
| 飞书 | `https://bridge.example.com/webhooks/feishu` |

## 11. HTTP 接口（部署后验收）

智能体只调这些路径（基址为 `WHATSAPP_BRIDGE_BASE_URL`）：

| 用途 | 方法 |
|---|---|
| 探活 | `GET /health` |
| 发文本/模板 | `POST /api/whatsapp/messages` |
| 列企业号 | `GET /api/whatsapp/phones`（可选 `?wabaId=`） |
| 列已批准模板 | `GET /api/whatsapp/templates`（可选 `?name=` `?wabaId=`） |
| 查会话窗口 | `GET /api/whatsapp/conversations?phone=&from=` |
| 创建 Onboarding Link | `POST /api/whatsapp/onboarding-links` |
| 查询 WABA 绑定 | `GET /api/whatsapp/wabas` |

常见业务码（HTTP 409）：

| code | 含义 |
|---|---|
| `WHATSAPP_WABA_REQUIRED` | 未绑 WABA，先嵌入式注册 |
| `WHATSAPP_FROM_NOT_IN_WABA` | `from` 不是当前 WABA 号码 |
| `WHATSAPP_TEMPLATE_REQUIRED` | 24h 窗口已关，必须发模板 |
| `WHATSAPP_PHONE_REQUIRED` | 当前 WABA 下列不到企业号 |

YCloud 429 会转成 `YCLOUD_RATE_LIMITED`，并带 `Retry-After`。

未绑 WABA 时列号/列模板会 400（缺少 `wabaId`）。

## 14. 排障

| 现象 | 排查 |
|---|---|
| 启动即退出 | 看终端/`journalctl`。常见是 `DATABASE_URL` 未加载或 Prisma 连错 schema |
| Prisma 报 shadow database | 改用 `npm run prisma:migrate:deploy`，不要 `migrate dev` |
| `GET /health` 通，Webhook 401 | 验签失败：Secret/Encrypt Key 不一致、body 被反代改写、服务器时间偏差 > 5 分钟 |
| 飞书保存事件 URL 失败 | 公网 HTTPS 不通，或 `url_verification` 被验签/加密拦住。先保证能返回 `challenge` |
| 买家来信没有进群 | YCloud 是否推到正确 URL；`WebhookEvent` 是否写入；飞书建群/发消息权限；日志里的 Feishu API 错误 |
| 话题回复不到 WhatsApp | 是否机器人自己的消息；是否 `@` 了人；是否未授权的其它机器人；24h 窗口是否已关 |
| 发消息 409 `WHATSAPP_WABA_REQUIRED` | 请求没带 `wabaId`，或 env 没有 `YCLOUD_WABA_ID`。智能体应从 env 读取后传入 |
| 列模板/列号 400 缺 wabaId | 必须带 `?wabaId=`（env `YCLOUD_WABA_ID`） |
| 绑定成功但重启后 `wabaId` 空 | 看 `.env.production` / `.env.development` 是否被回写了 `YCLOUD_WABA_ID`；不会从库回填 |
| env 文件没被回写 | 进程用户对 `.env.production` 无写权限。重启后需手动补 `YCLOUD_WABA_ID`，不会用库顶上 |
| 飞书 `open_id cross app` | `sourceOpenId` 必须是**本客服应用**的用户 open_id，不能用别的应用的 |

日志：Fastify 默认 stdout。systemd 用 `journalctl -u whatsapp-platform-bridge -f`。

## 15. 安全

- 密钥只放 gitignore 的 env 文件或密钥托管，权限 `600`。
- 不要在日志、监控、对话里打印 `YCLOUD_API_KEY`、飞书 Secret、Webhook Secret。
- 生产必须验签。`*_SKIP_SIGNATURE=1` 只给本机。
- Onboarding Link 有效期短、一链一次，只发给对应客户，不要贴到公开群或文档。
- 管理接口目前无独立鉴权，依赖网络隔离（仅内网 / 反代 IP 白名单）。不要把 `/api/*` 裸放到公网而不加网关。
- `onboardingUrl` 不要写入业务日志（代码按 PENDING 短期凭证处理）。
